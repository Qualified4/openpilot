# Pixel Ribbon v2: 혼합 주기 추적 및 전체 영상 후보 추출

2026-10-18, `ccnc-hda1`. **오프라인 실험만 구현했으며 실시간 적용·GPU 재학습·모델 승격은 보류한다.**

5Hz 정밀 도색 선택과 20Hz 원본 픽셀 추적을 결합했다. 동일한 물리 경계임을 확인하지 못한 관측은 공간 증거로 편입하지 않는다. 이 조건에서 기존 실사 5개 클립의 종류 확정률은 세 방식 모두 0%다. 혼합 방식은 전체 20Hz 정밀 방식보다 PC 비용이 줄었지만 50ms 예산을 충족하지 못했다. UNKNOWN 증가를 정확도 향상으로 해석하지 않는다.

## 2. 혼합 추적 구현

`hybrid_tracker.py`는 기존 오프라인 `PaintTracker`를 사용한다. 기존 daemon은 이 실험 모듈을 import하지 않는다.

- 정밀 keyframe은 실제 frameId 기준 4프레임마다 실행한다. 중간 프레임은 이전 목표 경계를 ego motion으로 원본 영상에 예측한 뒤 ±0.22m 탐색대에서 실제 색상·폭·방향을 다시 확인한다. 중간 프레임에서 RANSAC 경로 탐색을 반복하지 않는다.
- 입력 범위는 4.5–20m다. 이전 경계가 지원하지 않는 거리까지 외삽해 증거를 만들지 않는다. 원본 픽셀을 읽으며 영상 warp·리사이즈·검은 패딩으로 도색/공백을 만들지 않는다. HSV를 필요한 문맥에만 계산하고 좌표 역투영을 일괄 처리했다.
- 색상과 종류는 별도 상태다. 가까운 실제 도색만 색상 누적에 사용하며, 종류는 최근 3초의 고정 세계 경계에 0.25m 단위로 기록한다. 동일 물리 bin을 여러 프레임에서 봐도 별개 도색으로 세지 않는다.
- 공백은 도색 선택 실패와 다르다. 원본 노면 외관, 정적 노면 특징 대응, 동일 bin의 두 관측 및 최소 0.5m 이동이 필요하다. 도색 끝점은 공간 대응을 검증하는 데 쓸 수 있지만 끝점 자체로 노면 공백을 증명하지 않는다. 가림·미관측은 UNKNOWN이다.
- 실제 도색 끝점/주변 도로의 2차원 특징을 사용한다. 긴 실선의 aperture 특징을 배제하고 양방향 LK ≤0.8px, ego 예측 대비 ≤2px 및 ≤0.18m, 원본 patch NCC ≥0.85와 차선 후보 패치 대비 구별성 ≥0.05를 검사한다. 0.5m 거리 bin 3개 이상·2m span이 있어야 새 공간 증거를 받는다. **이 조건 통과도 독립적인 물리 위치 정답은 아니다.**
- 차선 변경·경계 추적 상실·시간/pose 불연속은 기존 reset을 유지한다. 마지막 대응 검증 후 0.3초 넘게 연결되지 않으면 공간 누적 체인을 초기화한다. 이전 결과를 다른 경계로 넘기지 않는다.
- 기존 종류 분류는 최소 세 도색 그룹·두 검증 공백 및 18m 관측을 요구한다. 실선 22m 조건도 유지했다. 실험용 대안 결과는 `alternative_type` 필드에만 기록한다.

기존 기본 동작을 바꾼 물리 대응 강제 검증은 새 subclass에만 있다. 리팩터링 전 코드를 별도 보존해 **동일 RGB 305프레임에서 기본 PaintTracker의 선택 mask와 모든 결과 필드가 일치**함을 검사했다(`regression.json`, 차이 0). 후보 일괄 역투영은 원래 계산과 픽셀/행 선택이 같고 부동소수 좌표 차이 1e-10 이내인지 테스트했다.

## 3. 동일 로그 비교 조건

기존 검수 분할의 train 4클립·validation 1클립을 유지했다. 각 클립은 약 3초, 고화질 영상 61프레임이다. 20Hz·혼합은 305프레임, 5Hz는 동일 시각의 80프레임을 관측한다. 비용은 좌우 독립 추적과 한 번의 전처리를 포함한다. 종류/색상 분석은 기존 검수 대상인 왼쪽 경계를 사용한다. 오른쪽은 비용 측정용이며 정답 정확도를 주장하지 않는다.

HEVC를 디코딩한 YUV420 평면의 U/V를 **RGB 왕복 없이** NV12로 배치했다. 각 방식은 같은 NV12 버퍼를 OpenCV RGB/gray로 변환한다. 실제 카메라 NV12 캡처가 아니며 codec·색 범위/행렬 차이가 있다. 기존 PyAV RGB와 절대 채널 차이의 프레임 평균을 평균하면 1.032/255다. 따라서 과거 RGB 실험과 이번 NV12 실험의 결과 차이를 추적 알고리즘 개선율로 주장하지 않는다.

실사 False Dashed 출력은 세 방식 모두 0이지만 점선 확정도 0이다. 독립적인 시퀀스 정답이 충분하지 않아 **실사 False Dashed 비율, 색상 정확도/노란색 재현율, Precision·Recall·F1, 실제 표시 전환 횟수, endpoint 누락률은 측정 불가**다. 종류 상태는 UNKNOWN으로 유지됐으며 실제 계기판 표시를 실행하지 않았다. 판정 지연을 0ms로 기록하지 않았다.

### 저속 실선 22m 조건과 대안

4.5–20m 단일 관측 창은 15.5m다. 원래 22m 실선 조건은 정차 시 충족할 수 없다. 저속에서는 관측 거리 외에도 유효 공간 대응의 지속성이 필요하다. 이번 엄격한 합성 실선은 0·1·2m/s 모두 3초 안에 원래 규칙으로 확정되지 않았다. 이전의 오차 없는 pose 대조에서 3m/s는 2.8초, 5m/s는 1.6초였으며, 이를 이번 실사 지연으로 주장하지 않는다.

대안은 실제 원본 도색이 보이는 전체 행에서 끊기지 않고, 최소 10m 연속 도색과 같은 물리 구간의 0.5초 중첩 관측이 있을 때만 `alternative_type=solid`를 기록했다. 정차 실선은 20Hz/혼합에서 61프레임 중 50프레임 확정됐다. 그러나 **18m 도색+5m 공백인 정차 긴 점선에서도 동일하게 50/61프레임을 실선으로 오판**했다(5Hz 12/16). 이 반례 때문에 대안을 채택하지 않는다. 보이지 않는 공백을 무시한 짧은 도색 연속성만으로는 실선을 입증할 수 없다.

## 5. PC 전체 처리 비용

Windows 11, AMD64 Family 25 Model 97, Python 3.12, OpenCV 4.13, OpenCV/BLAS 1스레드. 각 방식은 별도 프로세스에서 좌우를 함께 3회 실행했고, 영상 추출·합성 생성·테스트를 병행하지 않았다. 클립별 cold-start를 포함한다. 동작 순서는 5Hz → 20Hz → 혼합이며 실행 순서 랜덤화·장시간 열평형 시험은 하지 않았다.

포함: NV12→RGB/gray, 도색 선택, 정적 특징 검증, ego geometry, 3초 누적 및 종류·색상 판정, 실험 대안 계산. 제외: 비디오 codec 디코딩, 파일 입력 대기, 결과 저장/미리보기, 프로세스 시작. ONNX 호출은 0이며 아래 값은 ONNX 추론 지연이 아닌 **이 실험 전체 처리 지연**이다.

| 좌우 합계, PC 실측 | 5Hz 정밀 | 20Hz 정밀 | 혼합 |
|---|---:|---:|---:|
| 프레임 처리 평균 | 117.11ms | 111.11ms | 65.17ms |
| p95 | 171.35ms | 157.47ms | 135.93ms |
| p99 | 215.28ms | 184.28ms | 159.00ms |
| 전처리 평균 | 0.96ms | 0.91ms | 0.92ms |
| CPU 시간 / 영상 시간, 1코어=100% | 61.77% | 224.86% | 131.09% |
| 프로세스 샘플 peak RSS | 89.36MiB | 135.20MiB | 128.59MiB |

CPU 비율은 처리에 쓴 process CPU 시간을 입력 영상 14.991초로 나눈 부하 요구량이다. 작업 관리자 순간 사용률이나 실제 comma CPU 사용률이 아니다. Windows CPU 계수는 약 15.625ms 단위로 뛰므로 CPU 시간의 프레임별 p95/p99를 정밀 지연으로 해석하지 않는다. 지연 표는 고해상도 wall clock이다. RSS는 Python/import/입력 버퍼를 포함한 전체 프로세스 peak이며 기능 ON/OFF 증분 RSS가 아니다.

전체 20Hz 정밀 대비 혼합은 평균 지연 **41.35% 감소**, p95 **13.68% 감소**, p99 **13.71% 감소**, CPU 요구량 **41.70% 감소**다. 5Hz 대비 혼합 CPU 요구량은 **112.20% 증가**다. 종류 확정이 전혀 없어 비용 감소만으로 추천하지 않는다.

혼합의 정밀 프레임은 평균 108.88ms/p95 155.64ms, 경량 프레임도 평균 49.63ms/p95 81.22ms다. 3회 합계 915프레임 중 593프레임이 50ms 처리 예산을 넘었다. 입력 주기 50ms를 가정한 단일 직렬 worker 시뮬레이션의 최대 backlog는 1.80–1.93초였다. **이는 실제 카메라 프레임 드롭 측정이 아니다.** 현재 동기 구현은 PC에서도 20Hz 실시간 적용 조건을 통과하지 못한다. 비동기 keyframe 구조나 Snapdragon에서 더 빠를 것이라는 추정으로 통과 판정을 하지 않는다.

comma는 연결되지 않았다. Snapdragon CPU 지연·RSS·CPU ON/OFF, modeld/controlsd 주기, 실제 카메라 프레임 누락, CAN 표시 지연은 **측정 불가**다. RTX 4090은 사용하지 않았고 GPU 학습도 재개하지 않았다. 과거 Xiaoge 738ms/약160%/216MiB와도 입력·장치·측정 범위가 달라 실차 개선율을 계산하지 않는다.
