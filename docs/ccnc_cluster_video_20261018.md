## 확인된 표시 범위 — 사용자 확인 반영

### 차선 위치

| 위치 코드 | 실제 표시 의미 | 근거 |
|---|---|---|
| 0 | 차량 중앙 원점 | 사용자 확인, 84~85초 왼쪽 위치 0 |
| 1~45 | 왼쪽은 중앙에서 왼쪽으로, 오른쪽은 중앙에서 오른쪽으로 멀어지며 표시 | 사용자 확인 및 왼쪽 sweep |
| 46~63 | 차선 미표시 | 사용자 확인, 98.016초=45 표시 / 99.002초=46 미표시 |

**DBC 6비트 인코딩 범위 0~63과 이 계기판의 표시 유효 범위 0~45는 다르다.** 처음의 ‘화면 밖으로 이동한 후보’ 해석은 사용자의 확인으로 보완했다. 46 이상 미표시는 표시 코드 14 선택과도 다른 조건이다. 이 영상에서 오른쪽 위치는 주로 15에 고정돼 있어, 오른쪽 전 범위는 별도 직접 sweep 실측이 아닌 사용자 확인으로 분류했다.

코드와 화면의 실제 미터 간 비율, 선형성은 이 촬영으로 보정하지 않았다. DBC 위치 필드는 미터 단위 신호가 아니다. 코드 45를 별도 근거 없이 ‘실제 4.5m’로 확정하지 않는다.

### 곡률·방향 조합

| 방향 | 곡률 코드 | 표시 의미 |
|---|---|---|
| 좌(0) | 0 | 직진 |
| 좌(0) | 1~15 | 좌곡률 |
| 우(1) | 0~14 | 우곡률 |
| 우(1) | 15 | 유효 우곡률 범위 밖, 미표시 관측 |

이 비대칭 범위는 사용자가 현장 관측으로 확인했다. 방향과 무관하게 ‘곡률 0=직진’이라고 해석하면 안 된다. 직진 기준 조합은 **방향 0·곡률 0**으로 기록한다. 코드→물리 곡률(1/m), 좌우 동일 수치의 곡률 크기 대응식은 미측정이다.

120.003초의 `(방향0, 곡률2)`, 128.002초의 `(0,14)`에서 좌곡률, 129.004초 `(0,0)`에서 직진 복귀를 볼 수 있다. 136.006초 `(1,15)`에서는 두 차선이 보이지 않고, 140.000초 `(1,10)`에서는 우곡률이 다시 보인다.

135~139초는 14/15를 빠르게 오가며 카메라 화면과 UI가 엇갈린다. 예를 들어 UI가 15인 순간에 직전 값의 선이 남아 보이는 프레임이 있다. 따라서 이를 ‘15도 지원됨’이나 ‘원인 불명 랜덤 flicker’의 근거로 쓰지 않는다. 먼저 **우 방향 15의 유효 범위 초과와 화면 갱신 시차**로 분류한다. 통신 문제나 인식 오류로 확정하지 않았다.

## LF/LR 공통 거리 원점과 RF/RR 관계

사용자가 확인한 관계를 다음과 같이 기록한다.

| 관계 | 결론 | 증거 구분 |
|---|---|---|
| LF 거리0 ↔ LR 거리0 | 같은 화면 위치에 출력 | 영상 왼쪽 사례 + 사용자 확인 |
| RF 거리0 ↔ RR 거리0 | 동일한 관계 | 사용자 확인, 이 영상의 직접 오른쪽 비교 없음 |

LF=0의 증거는 [5.901초](../.analysis/ccnc-cluster-video-20261018-220338/vehicle-zero-detail/0005.901.png), LR=0은 [16.004초](../.analysis/ccnc-cluster-video-20261018-220338/frames/0016.004.png) 및 24.004초다. 모두 DETECT=6, 횡위치=3.0m로 읽힌다. [비교 crop](../.analysis/ccnc-cluster-video-20261018-220338/vehicle-zero-comparison.png)은 원본 좌표를 보존했고, 촬영 위치를 맞추려는 warp는 하지 않았다.

거리 0은 숨김을 뜻하지 않는다. 같은 횡위치·형태일 때 전측/후측 슬롯이 공통 표시 원점을 가지므로, **LF→LR, RF→RR 인계를 거리0에서 이어 붙이는 설계가 가능**하다. LF/LR 슬롯 이름만으로 거리0의 그림 위치가 서로 다르다고 판단하면 안 된다. 다만 이 관계가 전 거리 구간의 스케일·종방향 투영까지 같다는 뜻은 아니며, 동일 물리 차량의 후방 위치를 직접 측정한 증거도 아니다.

현재 HDA1에서 실제 후측방 레이더 객체 정보가 채워지지 않아 BSD 기반 표시를 쓰는 것과, 계기판이 LR/RR 도형 자체를 그릴 수 있는지는 구분해야 한다. 이 영상은 후자의 가능성을 보여준다.

## 사용자 제안: 확인된 옆 차량의 뒤쪽 슬롯 인계

**설계 제안으로 기록했고 구현하지 않았다.** 차선 인식·학습 작업과는 별개인 계기판 차량 표시 정책이다.

1. 실제 차량으로 확인돼 LF/RF에 표시되던 대상만 기억한다. 단순 점·벽·기둥·선택이 바뀐 다른 차량으로 후방 기억을 생성하지 않는다.
2. 자차가 앞서가 대상의 부호 있는 종방향 위치가 0을 통과하면 같은 쪽 LR/RR에 인계한다. 예: LF `0 → -1 → -2`에 대응해 LR `0 → 1 → 2`로 뒤로 보낸다. 전·후 슬롯에서 같은 차량을 중복 표시하지 않는다.
3. 가상 후측방은 16까지 뒤로 이동한 뒤 삭제한다. **16은 제안된 추적 종료 목표이며 이번 영상으로 검증한 하드웨어 숨김 경계가 아니다.**
4. 같은 쪽 BSD가 이미 켜져 있으면 가상 인계를 시작하지 않는다. 기존 BSD 표시를 우선한다.
5. 가상 인계 중 BSD가 켜지면 해당 가상 추적을 즉시 삭제하고, 기존 BSD 표시처럼 거리8로 수렴한다. ‘즉시’는 가상 기억 제거이며 표시 위치를 8로 순간 점프시키자는 뜻이 아니다.
6. BSD가 꺼지면 기존처럼 16 방향으로 퇴장시킨다. BSD 전의 오래된 가상 추적을 부활시키지 않는다.

상대 위치의 기본 적분은 `x(t+dt) = x(t) + (v_target - v_ego)·dt`다. 정지한 대상이면 자차 이동거리만 빼면 되지만, 주행 중인 옆 차량은 마지막 유효 상대속도/차량속도를 사용해야 한다. 예를 들어 자차20m/s·옆 차량18m/s라면 뒤로 밀리는 속도는 약2m/s이고, 자차 속도20m/s로 밀면 10배 빨리 사라진다. 미관측 중 무기한 같은 속도로 유지하면 안 되므로 후속 구현에서는 관측 나이·차선 변경·경계 상실·후진·대상 교체 시 기억 종료 조건을 검증해야 한다.

기존 코드에서 확인한 구현상 접점:

- 기존 selector와 radar map **두 경로 모두** BSD ON은 `distance.apply(8), DETECT=2`, OFF 후에는 `distance.apply(16), DETECT=1`을 사용한다. 어느 한 경로만 바꾸면 옵션별 동작이 달라진다.
- LR/RR 거리 필터 초기값은15, alpha는0.05다. 가상 인계 시작에 단순히 `apply(0)`만 호출하면 첫 출력이14.25여서 공통 원점0을 활용하지 못한다. 인계 시 실제 표시 원점에 맞춰 초기화하는 설계가 필요하다.
- 전측 거리에는 기존0.8 배율이 있다. 내부 실제 거리, 표시용 거리, 뒤쪽 거리의 변환을 맞춰서 인계 전후 속도/위치가 튀지 않게 해야 한다.
- 기존 실측 객체에는 `vRel/vLead`가 있고, radar map은 객체의 세계 속도와 자차 속도를 관리한다. 이를 재사용할 수 있는지 확인하는 편이 모든 차량을 정지 대상으로 가정하는 것보다 맞다. 현재 선택 경로는 앞쪽 객체에 제한이 있으므로 단순히 음수 거리의 live radar가 계속 들어온다고 가정할 수 없다.

의견: **공통 원점을 실제 영상으로 확인한 덕분에 타당성이 생긴 표시 연속성 개선안**이다. 다만 후측방 실측을 새로 얻는 기능은 아니다. BSD 우선·단일 대상·중복 방지·상대운동·기억 만료를 갖춘 오프라인 재생 실험 후 적용 여부를 판단해야 한다. 이번 기록 작업에서 전측/후측 CAN 출력은 바꾸지 않았다.

## 확인 불가 및 후속 근거

CAN 패킷, 송신·수신 timestamp, 각 UI 변경의 서버 승인 시각이 없어 실제 CAN 값과 반영 지연(ms)은 측정 불가다. 촬영 카메라/디스플레이/화면 녹화의 지연을 차량 제어 지연으로 보지 않는다. CPU·modeld/controlsd 주기·프레임 드롭·차선 분류 정확도도 이 영상에서 측정하지 않았다. 음성 전사 결과는 사용하지 않았다.

상세 값은 `observations.json`의31개 수동 관측, `timeline.csv`, `display-constraints.json`에 저장했다. 전사 항목은 해당 프레임에서 읽히는 필드만 넣었으며 화면 밖 값을 이전 상태로 채워 실측처럼 만들지 않았다. 구간 전체 유효 범위와 RF/RR 동일 동작은 사용자 확인임을 명시했다.

복사·프레임 추출·기록 재현 스크립트는 분석 폴더의 `extract.py`, `dense_curve.py`, `record.py`다. 이미 확보한 복사본으로 실행하며 runtime import나 송신은 없다. 기존 보고서의 ‘실차 표시 미검증’은 당시 기록으로 보존하고, 이번 증거를 별도 문서로 추가했다.
