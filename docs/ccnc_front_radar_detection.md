# CCNC 전방 차량 검출 및 계기판 표시 로직

이 문서는 CCNC 계기판에 LF(전방 좌측), FF(전방 중앙), RF(전방 우측) 차량을 각각 최대 1개 표시하는 현재 구현을 설명합니다. 확인일은 2026-09-13이며, 차량 제어용 선행차 선택이나 클러스터 HUD 전체의 동작을 설명하는 문서는 아닙니다.

## 지원 대상

### 2026-09-24 표시 좌표 보완

- 측면 데드밴드 중심은 양쪽 차선 확률이 모두 0.6 이상이고 유한한 좌표·증가하는 x·올바른 경계 순서가 확인될 때만 갱신합니다. 유효하지 않으면 마지막 정상 중심을 유지합니다. 데드밴드 곡선과 중심 필터 속도는 유지합니다.
- 연속 대상의 횡위치는 3개 호출 샘플 Median을 먼저 계산합니다. 출력과 Median의 차이가 0.6m를 넘으면 즉시 재설정하는 대신 초당 최대 5m로 따라가며, 목표에 도달하면 기존 alpha 0.3 필터로 돌아갑니다. 속도 제한은 100Hz frame 차이로 계산합니다. 새 대상·관측 불연속·15frame 초과 공백은 새 위치에서 즉시 시작합니다. 종거리 필터와 일반 `NoiseFilter`는 변경하지 않습니다.
- 동일 기준의 곡률 보정량(`aligned_y - raw_y`)은 근거리/경로에서 기존 0.6m 급변 완충을 유지합니다. 60m 초과 차선 기준에서는 작은 변화도 시간에 따른 속도 제한을 적용합니다. 보정량 접근 속도는 60m의 3m/s에서 120m의 1.5m/s까지 선형으로 줄고 이후 1.5m/s를 유지합니다. 원시 레이더 횡이동은 이 보정량 제한에 포함하지 않습니다. 기준 전환 bias는 계속 해제하며, 진행 중 곡률 완충은 현재 목표로 재계산해 단발성 보정 튐의 잔상을 줄입니다.
- 차선 소실 시 경로 FF의 기존 대상 여유는 최근 **FF**에만 적용합니다. LF/RF 이력만으로 FF 유지 여유를 얻지 않습니다. 양쪽 내부 차선이 모두 확률 0.6 이상이고 좌표·범위·경계 순서가 유효할 때 확인한 차선 밖 관계(경계 여유 0.35m)는 최대 1초/자차 이동 15m까지 기억합니다. 해당 이력이나 최근 측면 표시 이력이 있으면 현재 영상 일치와 경로 잔여 횡거리 1.2m 이내를 모두 만족해야 경로 FF가 됩니다. 새 관측 세대·점 소실·관측 공백에서는 이력을 버리고 신뢰 가능한 차선 안으로 들어오면 즉시 해제합니다. 약한 현재 차선 경계만으로 제외하지 않습니다.

세 가지 보완 직후(아래 상쇄 보존 완화 이전), 직전 Median 순서 보완 코드 대비 36개 로그(41,509개 출력 시점)의 연속 FF 표시 급변은 51→27회, 최대 변화는 1.064→0.460m 상당입니다. 급변은 같은 ID/관측 세대, 연속 표시, 시간 간격 0.1초 이하에서 `FF_LATERAL`이 0.3m 넘게 변한 경우이며 실제 차량 이동량이나 오검출 건수가 아닙니다. 최초 두 보완 이전의 284회/2.387m와 비교하면 큰 감소지만, 356/2는 0→1회, 366/0은 1→2회로 작은 급변이 증가했습니다. 데드밴드 전 필터의 속도 제한이므로 CAN 좌표 변화가 항상 0.25m 이하라는 뜻도 아닙니다.

전체 78개 로그의 90,309개 출력 시점을 비교했습니다. FF 선택이 달라진 것은 108개 시점/11개 시간 구간이며, 그중 FF 표시 유무는 84개 시점에서 바뀝니다. 356 전체22개·358 전체12개·38a 세 구간의 검출 여부와 선택 ID는 유지됩니다. 366/47의 26.25–26.91초 중13개 시점은 기존 ID55를 FF 대신 RF로 표시하고, 47.51–48.45초20개 시점은 ID55를 RF에 두며 ID57을 FF로 선택합니다. 366/30은 일부 FF가 LF로 옮겨집니다. 변경된11개 구간의 대표 영상 프레임을 대조했지만 원거리 대상 대응과 모든 물리적 차로 정답을 확정한 검증은 아닙니다.

지속적인 1.2m 계단 입력의 합성 검사에서는 Median의 첫 호출 보류 이후 50ms 간격으로 최대0.25m씩 접근해 약0.25초에 도달합니다. 이전 즉시 재설정보다 약0.2초 느리며, 실제 끼어들기·차선 변경 반응은 실차 확인이 필요합니다. Median은 독립 레이더 관측 수가 아닌 표시 필터 호출 샘플입니다. 161개 격리 회귀 테스트 통과. 사용자 지정 `ccnc-hda1`에만 로컬 반영하며 커밋·푸시·NAS 배포는 하지 않았습니다.

### 원거리 레이더·곡률 상쇄 보존

356 전체 재생에서 구간2의31–33초 원시 횡위치와 곡률 보정량이 반대로 변하며 상쇄되는 상황을 확인했습니다. 보정량만 제한하자 상쇄가 깨져32.78초의 보정 목표는 오른쪽1.434m인데 필터 출력은 왼쪽1.294m까지 밀렸습니다. 원거리 추적점의 실제 물체 위치를 영상 정답으로 확정한 것은 아닙니다.

현재는60m 초과·동일 차선 기준에서 두 변화의 부호가 반대이면 `min(abs(raw_change), abs(geometry_change))`만큼 보정량 접근 허용치를 추가합니다. `geometry_change`는 이전 bias를 제거한 실제 모델 보정 목표끼리 비교합니다. 상쇄되는 몫만 함께 반영하고, 남은 곡률 변화에는 기존 속도 제한을 적용합니다. 원시 횡이동이나 모델 보정량을0으로 고정하지 않으며, 기준 전환 완충·근거리/경로 처리·5m/s 횡필터·데드밴드는 그대로입니다.

356/2의32.78초 출력은 오른쪽1.529m로 목표를 따라가며,31–34.5초 ID57의 최대 필터–목표 차이는2.889→0.597m로 감소했습니다. 이 값은 계산된 목표와 표시 필터 사이 차이이며 물리적 위치 오차가 아닙니다. 양방향 상쇄, 상쇄되지 않은 모델 급변 제한 및 기존 bias 해소를 포함한164개 격리 테스트를 통과했습니다. 21번 빠른 횡단 대상의5m/s 추종 지연은 이번 원거리 보완의 해결 범위에 포함하지 않습니다.

완화 전후78개 로그90,309개 출력 시점에서 FF/LF/RF 검출 값·선택 ID·횡위치를 제외한 모든 차량 표시 값이 일치했습니다.356/13 차로 변경 차량ID33의 횡필터 출력과57.71초 FF→LF 전환은 동일합니다. 기존 코너36개 로그의 FF 급변은27→24회, 최대0.460m로 유지됐습니다.356전체 FF 급변은22→21회이며, 전체78개에서는 FF68→64회/LF104→102회/RF69→70회입니다. RF의 작은 급변1회 증가는 남으며 각 슬롯의 전체 최대 급변은 변하지 않았습니다.366/45 FF 급변4회는 유지되고366/46의 최대 변화는0.300→0.223m입니다. 로그 재생 결과이며 실차 결과는 아닙니다. 커밋·푸시·배포하지 않았습니다.

이 기능은 **HDA1 차량만 지원**합니다. 코너 레이더가 없는 차량에서도 전방 레이더의 `liveTracks`를 이용해 **좌우 차선의 차량을 계기판에 표시**할 수 있도록 지원합니다. 좌우 차량 표시는 LF(전방 좌측)와 RF(전방 우측)에 각각 최대 1개씩 출력합니다.

## 처리 흐름

```text
유효하고 신선한 liveTracks + modelV2
  → 보정 기준 내부 차선 선택
  → 출처·거리·유한값 검사
  → 새 레이더 관측의 연속 추적 갱신
  → 차선 투영값 일괄 계산·캐시 및 속도 조건 조기 제외
  → 원본 차선 좌표로 FF/LF/RF 분류 및 곡률 보정
  → FF 속도 검사 / LF·RF 속도·횡거리·경계·차로폭 검사
  → 각 슬롯에서 원본 제곱거리가 가장 작은 후보 선택
  → 불확실한 차선의 보조 FF 선택
  → 기존 FF의 좁은 경계 공백 보완(정상 측면 전환 우선)
  → 거리·횡위치 필터 및 CCNC 신호 출력
```

## 1. 입력과 표시 전제

`card.py`는 유효한 레이더 결과를 `self.live_tracks`에 보관합니다. `apply()`에는 다음 조건을 만족할 때만 전달합니다.

```python
0 <= now_nanos - self.live_tracks_time < 150_000_000
```

즉 입력 나이가 150ms 미만이어야 합니다. `CS.live_tracks`가 없으면 후보를 지웁니다. 차선 확률이 0.1 미만이면 LF/RF의 차선 분류는 중단하지만 FF는 모델 경로와 영상 선행차를 이용한 보조 선택을 수행합니다. CCNC 0x162 처리 분기가 실행되는 것이 전제입니다.

CANFD 후보 선택은 `radar_state`를 사용하지 않습니다. `card.py`의 `radarState` 구독은 유지되어 있지만 `apply()`로 전달하지 않습니다.

## 2. 보정 기준 차선 선택

내부 차선은 `laneLines[1]`과 `laneLines[2]`입니다. 경계 좌표는 다음을 검사합니다.

- x/y 길이가 같고 2개 이상.
- 모든 좌표가 유한값.
- x가 엄격히 증가함.

기본적으로 확률이 높은 내부 차선을 선택하며 최초 동률이면 오른쪽입니다. 선택된 차선 확률이 0.1 미만이면 즉시 재선택합니다. 반대편 확률이 0.1 이상 높은 상태가 30 제어 프레임 지속되면 기준을 전환합니다. 제어 프레임은 100Hz 기준이므로 약 0.3초입니다. 양쪽 모두 0.1 미만이면 선택 상태를 초기화합니다.

외곽 차선은 `laneLines[0]`, `laneLines[3]`이며 확률이 **0.1 초과**이고 좌표가 유효할 때 사용합니다. 로드엣지는 `roadEdges[0]`, `roadEdges[1]`의 좌표 유효성을 검사합니다. `roadEdgeStds` 값으로 경계를 제외하지 않습니다.

## 3. 기본 후보 필터

- `radarSource == "frontRadar"`만 허용합니다. 순정 SCC와 코너 레이더는 이 전방 후보에서 제외합니다.
- `dRel >= 1m`이어야 합니다.
- `dRel`, `yRel`, `vRel`, `vLead`가 모두 유한값이어야 합니다.
- `modelProb`이나 `trackState` 숫자로 직접 제외하지 않습니다. 상태 3을 추적 상실로 단정하는 조건도 없습니다.

## 3-1. 2026-09-23: 최초 관측의 경계 정지점 제외 (초기 구현)

아래는 `6cf169ec`의 초기 구현과 검증 기록입니다. 최초 검출은 3-2절, FF 추가 확인은 3-3절, 현재 정지 저장 정책은 3-5절을 따릅니다.

`hyundaicanfd_ccnc.py`의 `update_boundary_admission()`은 최초 관측 때 정지해 있던 점이 차선 경계에 붙어 있는지 확인합니다. 원본 `liveTracks`나 주행 제어용 선행차를 수정하지 않는 CCNC 표시 전용 조건입니다.

- 최초 추정 종속도 `vLead`와 횡속도 `yvRel`의 절댓값이 각각 2km/h 이하인 점만 최초 0.3초를 검사합니다. 이미 움직이던 점이나 최초 확인을 마친 점이 나중에 경계에서 멈추는 경우에는 이 조건을 새로 적용하지 않습니다.
- 확률 0.1 초과이며 좌표가 유효한 모델 차선 4개를 사용합니다. 점의 `dRel` 위치에서 보간하며 경계 x 범위 밖으로 외삽하지 않습니다. 레이더/모델 y 부호를 맞춘 거리가 0.3m 이하면 근접 관측입니다.
- 첫 0.3초 동안 서로 다른 레이더 관측 중 최소 3회이면서 절반 이상이 정지·경계 근접이면 제외를 유지합니다. 확인 중에도 근접 관측이 생긴 후보는 일단 표시하지 않습니다. 같은 레이더 메시지를 반복 처리해도 확인 횟수는 늘지 않습니다.
- 최초 프레임에서 차선 확률이 낮아도 이 짧은 구간 안에서 확인할 수 있습니다. 확정 후에는 차선 확률/위치 변화나 관측 시간 누적으로 제외를 해제하지 않습니다.
- 제외된 점은 종방향 또는 횡방향 속도가 2km/h를 초과한 채 같은 방향으로 0.5초 이상 이어지고, 해당 방향 위치 변화도 0.5m 이상 확인돼야 다시 허용합니다. 종방향은 자차 이동거리를 보상합니다. 회전 보정은 사용하지 않습니다.
- 점의 소실, 기존 연속성 판정의 불연속/ID 재사용, 긴 제어 간격에서는 최초 관측 이력을 초기화합니다. 같은 ID의 신규 제외점이 과거 정지 표시를 되살리지 않도록 저장된 표시도 검사합니다.
- 직접 FF/LF/RF 선택뿐 아니라 영상/경로 FF 보완과 차선 소실 보완에도 같은 제외를 적용합니다. `Std`, 차량 종류 분류 또는 새 사용자 설정은 사용하지 않습니다.

## 3-5. 현재 정지 저장 정책: 자차 정지 중 큰 횡이동만 추가 제한

- 자차 속도 절댓값이 0.3km/h 이하일 때만 횡이동 이력을 수집합니다. `observe()`가 동일 객체로 판정한 연속 트랙의 새로운 레이더 관측만 사용하며, 점 소실·불연속·ID 재사용 시 이력을 잇지 않습니다.
- 최근 1초 안에 최소 0.5초의 관측이 있고, 순 횡이동이 0.75m 이상일 때 검사합니다. 같은 방향의 0.04m 이상 변화가 최소 3번이고 순 이동이 누적 절대 이동의 80% 이상이어야 합니다. 한 번의 변화가 순 이동의 60%를 넘으면 단발 튐으로 보고 제외합니다.
- 위 조건을 만족한 점은 현재의 실제 검출 표시를 막지 않고, 정지 표시의 저장과 저장된 잔상만 해제합니다. `yvRel=0`이어도 실제 좌표 변화로 검사합니다. 자차 이동 중의 좌표 변화는 이 횡단 이력으로 사용하지 않습니다.
- 이후 종위치 0.3m/횡위치 0.2m 범위와 종속도·상대속도 각각 2km/h 이하를 2초 유지하면 저장 금지를 해제합니다. 기존 저장 확인을 다시 거치므로 실제로 옆으로 움직였다가 정차한 차량을 영구적으로 제외하지 않습니다.
- 저장에는 최초 관측 시각을 계속 포함합니다. 재사용된 ID의 먼 새 점이 예전 물리적 위치의 저장을 취소하거나, 새 점의 횡단 이력을 예전 저장에 적용하지 않게 구분합니다.

18개 구간을 다시 재생했습니다. 358의 3구간 RF와 11구간 LF 유지가 보존됐고, 358 전체의 직접 FF/LF/RF 선택은 유지 보완 전과 동일합니다. 횡단보도 ID38의 27~58초 저장 잔상은 0, 306의 31~35초 LF는 0이며 기존 4·5번 정지점 제외와 정상 차량 관찰창도 유지됐습니다. 테스트 146개 통과: 단발 튐, 왕복 흔들림, 동일 메시지 반복, 자차 이동, ID 재사용, 실제 횡이동과 2초 정지 후 복구를 포함합니다.

0.75m/1초 등은 현재 로그에서 확인한 휴리스틱입니다. 더 느린 횡단, 여러 물체 사이의 연속적으로 보이는 레이더 연계, 실제 차량의 큰 측면 이동을 완벽하게 분류한다는 의미는 아닙니다. 실차 검증은 남으며 커밋·푸시·NAS 배포는 하지 않습니다.

## 4. 속도 기준

`velocity = vLead * 3.6`으로 변환한 추정 절대 종방향 속도(km/h)를 사용합니다. 기준값은 자차 속도에 따라 선형 보간하며 보간 범위 밖에서는 끝값을 사용합니다. 통과 비교는 모두 **기준값 초과**입니다.

| 후보 | 자차 속도 → 후보 속도 기준 (km/h) |
|---|---|
| FF | 30 → -100, 40 → 0, 100 → 20 |
| 일반 LF/RF | 0 → 2, 30 → 10, 100 → 20 |
| 저속 LF/RF 예외 | 10 → -1, 40 → 10; 추가로 `dRel < 30m` |

FF는 `a_ego_kph < -3`이면 속도 기준을 -100km/h로 완화합니다. 여기서 `a_ego_kph`는 `aEgo * 3.6`이며 단위는 km/h/s입니다. 원래 가속도 기준으로 약 -0.833m/s² 미만입니다.

세 속도 경로 중 어느 것도 통과할 수 없는 점은 후보별 분류·경계 검사 전에 제외합니다. 차선 투영값은 새 모델/레이더 관측에 대해 일괄 계산해 재사용합니다. 일반 측면 속도 기준을 통과하지 못해도 저속 예외 조건을 만족하면 LF/RF 후보가 될 수 있습니다.

## 5. 원본 좌표 분류와 곡률 보정

레이더 `yRel`은 왼쪽이 양수입니다. 모델 차선의 y는 부호를 반전해 같은 좌표계로 맞춥니다.

```python
left_inner_bound = -interp(dRel, left_inner_x, left_inner_y)
right_inner_bound = -interp(dRel, right_inner_x, right_inner_y)
```

경계값이 유한하지 않거나 `right_inner_bound >= left_inner_bound`이면 해당 점을 제외합니다.

| 슬롯 | 원본 yRel 조건 |
|---|---|
| FF | `right_inner_bound <= yRel <= left_inner_bound` |
| LF | `yRel > left_inner_bound` |
| RF | `yRel < right_inner_bound` |

슬롯 분류는 보정 전 값으로 수행합니다. 계기판 출력용 횡위치는 다음과 같이 보정합니다.

```python
road_aligned_yRel = yRel + (lane_y_at_drel - selected_lane_y0)
```

선택 차선의 해당 거리 y에서 시작점 y를 빼서 도로의 휘어짐을 보정합니다. 차선 기반 처리에서는 `model.position`이나 2차 방정식을 사용하지 않습니다. 차선 소실 시 FF 보조 경로에서만 `model.position`을 사용합니다. 내부 차선 보간은 `np.interp`이므로 x 범위 밖에서는 끝값을 사용합니다. 외곽 차선·로드엣지 검사는 해당 dRel이 각 경계의 x 범위 안에 있을 때만 적용합니다.

LF/RF는 후보 선택 단계에서 `abs(road_aligned_yRel) <= 5.4m`를 만족해야 합니다. FF에는 이 측면 제한을 적용하지 않습니다.

## 6. 새 레이더 관측의 연속성

`_CcncRadarDisplayTracker`는 card가 새 RadarData 객체를 전달했을 때만 관측을 갱신합니다. 동일 객체를 제어 루프에서 반복 처리해도 관측 수나 관측 지속 시간이 늘어나지 않습니다.

- 기본 후보 출처/유한값/거리 검사를 통과한 점을 추적합니다.
- 서로 다른 관측의 간격은 최대 0.15초입니다.
- 거리 예측 오차는 `1 + 2 * dt` m 이하, 횡위치 변화는 `0.5 + 5 * dt` m 이하입니다.
- LF/RF 후보는 최소 3회 관측 및 관측 시각 기준 0.15초 지속 조건을 통과해야 합니다.
- 일반 측면 속도 조건과 0.3초 지속 조건을 함께 통과하면 외곽 차선 바깥 0.75m 여유를 허용합니다.
- 새 관측에서 사라진 ID는 제거하고, 입력 소실/프레임 역행/긴 실행 간격은 이력을 초기화합니다.

### 기존 LF/RF의 단발성 횡좌표 변화 예외

직전 LF 또는 RF로 선택한 동일 ID에 한해서, 기본 횡변화 한계를 조금 넘더라도 다음 조건을 모두 만족하면 관측 시작 시각과 관측 수를 이어갑니다.

- 이전까지 3회 이상, 0.15초 이상 연속 관측된 트랙.
- 관측 간격은 0초 초과~0.15초 이하, 종거리 예측 오차는 기존 `1 + 2 * dt` m 이하.
- 횡좌표 변화는 `0.75 + 5 * dt` m 이하(기본 한계보다 0.25m 추가).
- 이전 관측 대비 `vRel` 변화는 1m/s 이하.
- 동일 ID에 이 예외를 적용한 뒤 최소 0.3초 경과.

예외를 적용하면 **선택 자격은 유지하지만 해당 ID의 위치 필터는 초기화**합니다. 현재 관측 좌표로 다시 필터를 시작하며 과거 위치를 고정 출력하지 않습니다. 속도·경계·차로폭·거리 조건은 계속 적용하므로 선택을 무조건 보장하지 않습니다. 새 후보나 직전 FF에는 이 예외를 적용하지 않습니다. 반복 횡변화나 종방향 불연속은 기존 초기화 규칙을 따릅니다.

이는 가드레일 판별기가 아닙니다. 지속적으로 관측되는 잘못된 트랙은 통과할 수 있습니다.

## 7. 외곽 차선과 로드엣지 여유

| 후보 상태 | 외곽 차선 | 로드엣지 |
|---|---|---|
| 연속 추적 조건을 통과한 주행 후보 | 바깥으로 0.75m 허용 | 안쪽으로 0.95m 제한 |
| 그 외 후보: 초기 주행 후보 또는 저속 예외 후보 | 안쪽으로 0.25m 제한 | 안쪽으로 0.95m 제한 |

직전에 같은 측면 슬롯에서 선택한 ID에는 외곽 차선 여유를 추가로 0.3m 줍니다. 신규 진입과 기존 유지의 기준을 구분해 경계 부근의 반복 교체를 줄입니다. LF/RF의 로드엣지는 후보 수용 범위를 **안쪽으로 0.95m** 제한합니다. 일반 FF 분류에는 이 측면 경계 검사를 적용하지 않습니다. 각 경계에 여유를 먼저 적용한 뒤 더 엄격한 경계를 선택합니다. 유효한 경계만 포함하며 둘 다 없으면 측면 후보를 선택하지 않습니다.

```python
lane_margin = 0.75 if allow_lane_margin else -0.25

# 두 경계가 모두 유효한 경우. 원본 레이더 좌표 기준.
left_effective_bound = min(left_outer_bound + lane_margin,
                           left_edge_bound - 0.95)
right_effective_bound = max(right_outer_bound - lane_margin,
                            right_edge_bound + 0.95)
```

LF는 `yRel < left_effective_bound`, RF는 `yRel > right_effective_bound`이어야 합니다. 경계와 정확히 같은 값은 통과하지 않습니다.

## 8. 차로폭 조건은 확장 전 경계로 검사

차선 바깥을 0.75m 허용해도 실제 차로가 넓어지는 것은 아닙니다. 폭 검사는 기존의 안쪽 0.25m 여유를 적용한 경계로 유지합니다. 후보 수용 범위의 로드엣지 0.95m 축소와는 별도 계산입니다.

```python
left_width_bound = min(valid_left_raw_bounds) - 0.25
right_width_bound = max(valid_right_raw_bounds) + 0.25

left_width_bound - left_inner_bound > 1.8
right_inner_bound - right_width_bound > 1.8
```

목록에는 유효한 원본 외곽 차선·로드엣지만 포함합니다. 이 조건은 차량의 폭이나 차량과 경계 사이 여유를 재는 것이 아니라, 옆 차로가 있을 만한 공간을 검사합니다. 원본 내부 경계와 선택된 외부 경계의 간격은 사실상 **2.05m 초과**여야 합니다.

## 9. 각 슬롯에서 가장 가까운 후보 선택

```python
dist_score = dRel * dRel + yRel * yRel
```

원본 좌표의 제곱거리로 비교하며 제곱근은 계산하지 않습니다. 조건을 통과한 후보 중 최소값을 LF/FF/RF 각각 선택합니다. 동일 점수이면 먼저 선택된 후보를 유지합니다. 하나의 점은 분류에 따라 한 슬롯에만 들어갑니다. 이전 ID에도 경계와 속도 조건을 적용하며, 허용 후보 사이의 최소 제곱거리 원칙은 유지합니다. FF 보조 선택과 측면 선택이 겹치면 FF 한 슬롯에만 표시합니다.

## 9-1. 차선 없는 구간의 FF 보조 선택

차선 확률이 0.1 미만이면 보조 선택으로 전환합니다. FF의 차선 처리 복귀는 확률 0.3 이상이면 즉시 수행합니다. 표시 공백 억제를 위해 이전 FF 슬롯을 오래 유지하지 않습니다.

- 유효한 모델 경로의 x 증가 구간만 사용합니다. 코너에서 먼 경로가 x 방향으로 되돌아가는 부분은 제외합니다.
- 경로 범위 안, 최대 80m의 연속 관측 후보만 사용하고 기존 FF 속도 기준을 적용합니다.
- 경로 잔여 횡거리 기준은 최근 0.3초 이내 표시한 연속 관측 차량 1.8m, 일반 신규 후보 1.2m입니다. 신규 후보는 영상 선행차 일치도 필요합니다. 아래의 근거리 영상 강일치 조건에서는 2.0m를 허용합니다.
- 영상의 현재 선행차 `leadsV3[0]`를 사용합니다. 확률은 기존 FF 0.3 이상, 신규 0.5 이상입니다. 모델의 미래 시점 선행차는 사용하지 않습니다.
- 영상/레이더 원점 차이 1.52m와 횡방향 부호를 보정합니다. 종거리 차이 한계는 기존 FF `max(8m, dRel*0.2)`, 신규 `max(6m, dRel*0.2)`이고, 횡위치 차이는 1.5m, 속도 차이는 5m/s 이하여야 합니다.
- 직전 표시 차량이 영상과 일치하면 경로 잔여 횡거리 4.5m까지 FF 후보로 허용합니다. 출력 횡위치는 경로 보정값을 사용하며 0으로 강제 고정하지 않습니다. 경로 자체의 오차가 있으면 출력에도 잔여 횡편차가 나타날 수 있습니다.
- 현재 트랙이 사라지거나 관측이 불연속이면 선택 신원 이력을 지웁니다. 표시되지 않아도 관측이 계속되면 신원 이력만 최대 0.3초 유지하며, 검출 조건은 현재 좌표로 다시 검사합니다. 이전 좌표를 고정 출력하지 않습니다.
- 동일 트랙의 차선/경로 보정 기준이 바뀌면 실제 레이더 횡이동을 보존한 채 기준 변화분에만 전환 오프셋을 적용하고 최대 3m/s로 감소시킵니다. 필터 및 보정 이력은 트랙 ID별로 공유합니다.

## 9-2. 기존 FF의 내부 차선 경계 공백 보완

정상 분류와 보조 FF 선택 후 FF가 비어 있을 때만 적용합니다. 후보는 직전 FF와 같은 ID이며, 연속 관측과 최근 FF 이력이 유효해야 합니다. 선택 차선 확률 0.1 이상인 차선 처리 경로에서 현재 FF 속도 기준과 유효한 내부 경계를 통과해야 합니다.

```python
right_inner_bound - 0.35 <= yRel <= left_inner_bound + 0.35
```

이 범위의 기존 FF가 LF/RF에도 선택되지 않았을 때만 FF로 이어줍니다. 정상 LF/RF로 선택되면 즉시 해당 슬롯으로 이동하며, 다른 FF가 이미 선택됐다면 덮어쓰지 않습니다. 출력에는 현재 관측값과 차선 곡률 보정을 사용합니다.

이 규칙은 LF/RF의 차로폭·로드엣지 필터를 완화하지 않습니다. FF의 빈 슬롯을 보완하는 별도 규칙이며, 차선 확률 0.5 이상에서도 적용할 수 있습니다. 경계 여유 밖으로 이동하거나 트랙이 사라지면 과거 좌표로 표시를 연장하지 않습니다. 경계 여유 안에 계속 있으면 연속 선택될 수 있으며 별도의 최대 유지 시간은 없습니다.

## 10. 계기판 출력

- 거리와 횡위치 `NoiseFilter`는 슬롯이 아닌 트랙 ID별로 관리합니다. 같은 차량이 LF→FF→RF로 옮겨도 필터를 초기화하지 않습니다. 거리에는 필터 적용 후 0.8을 곱합니다.
- 공통 좌표계의 횡위치를 트랙별로 필터링한 뒤 슬롯별 부호와 곡선 데드밴드를 적용합니다. 다른 트랙의 필터 상태는 넘기지 않습니다. 관측 불연속/소실이면 이력을 지우고(6절의 측면 예외는 선택 이력만 보존), 표시 공백이 0.15초를 넘으면 위치 필터를 초기화합니다.
- FF는 보정 횡위치의 부호를 반전해 출력합니다.
- LF는 보정 횡위치, RF는 반전한 보정 횡위치를 사용하며 최종 CAN 횡거리 범위인 0~12.7로 제한합니다.
- 저속 측면 후보를 ±2.5m로 강제 이동시키지 않습니다. 저속에서도 슬롯을 넘을 때 공통 보정 횡위치가 이어지도록 합니다.
- 후보가 없으면 해당 `*_DETECT`를 0으로 설정합니다. 거리·횡위치 필드가 반드시 0이 되는 것은 아닙니다.

위 내용은 정상 처리 경로입니다. 현재 큰 `try/except`에서 예외가 발생하면 기존의 고정 거리·검출값을 설정하는 별도 경로가 남아 있습니다. 따라서 모든 오류 상황에서 표시가 꺼지는 것은 아닙니다.

### 후측방 LR·RR 표시와 주의사항

후측방 LR(좌측 후방)·RR(우측 후방)은 BSD(사각지대 감지) 신호가 감지되면 해당 방향의 **고정된 표시 위치에 차량 형상을 출력**합니다. 전방 LF·FF·RF처럼 레이더로 측정한 개별 차량의 거리와 횡위치를 표시하는 방식이 아닙니다.

> **주의:** LR·RR 차량 형상은 해당 방향의 BSD 감지 상태를 알리는 표시입니다. **실제 차량까지의 거리나 정확한 위치를 나타내지 않습니다.** 차량 형상의 위치나 간격을 근거로 차간거리 또는 차선 변경 가능 여부를 판단하면 안 됩니다.

구현에는 표시 전환을 위한 거리 필터와 차로 중심 오프셋 보정이 포함되어 있어 차량 형상의 위치가 일부 변할 수 있지만, 이 변화 역시 실제 후측방 차량의 이동이나 측정 거리를 의미하지 않습니다.

## 11. 최적화와 한계

모델 객체와 타임스탬프를 기준으로 차선 배열·유효성 결과를 캐시합니다. 새 레이더 관측에서 기본 조건을 통과한 점의 필드 값을 한 번 추출하고, 모델/레이더가 바뀔 때 차선 투영값을 일괄 계산해 재사용합니다. 속도 기준과 위치 필터의 보간은 스칼라 계산을 사용합니다.

### LF/RF 종거리 상한 (2026-09-12)

LF/RF 후보는 원시 `dRel <= 80m` 조건을 통과해야 합니다. 이 검사는 `lf_lead`/`rf_lead`를 선택하기 전에 적용하며, FF 거리 범위는 변경하지 않습니다. 두 경로의 기존 선택 결과에서 70~80m 후보가 각각 약 8.49초와 19.92초 관측되어, 해당 구간을 보존하는 80m를 상한으로 선택했습니다. 이는 모든 후보가 실제 차량임을 보장하는 수치는 아닙니다.

`00000358--de86ef734b --7` 33.04~33.34초의 약 111m 대체 RF는 제외되지만, 기존 ID53이 경계 검사에서 탈락하는 원인은 그대로여서 그동안 RF 표시 공백이 생길 수 있습니다. 거리 상한은 먼 차량으로의 순간 교체를 막는 규칙이며 경계 판정을 우회하지 않습니다.


### 불확실한 차선에서 FF 보완 (2026-09-12)

- 선택한 차선 확률이 0.5 미만이면 차선 모드가 켜져 있어도 보조 FF를 검토합니다. 0.5 이상인 차선 판정은 이 보완으로 덮어쓰지 않습니다.
- 차선 모드에서 보조 후보를 사용하려면 현재 영상 선행차와 일치해야 합니다. 기존 차선 FF가 있으면 최근 0.3초 안에 FF로 표시한 트랙만 이를 대체할 수 있고, 원시 제곱거리도 기존 후보 이하이어야 합니다.
- 보조 FF 검색이 실패해도 최근 FF로 표시한 연속 관측 차량의 차선 판정 결과는 유지합니다. 다만 차선 복구 전의 약한 차선만으로 새 FF를 도입하지는 않습니다. 출력 보정 기준도 실제로 사용한 차선/경로에 맞춰 유지합니다.
- 근거리 영상 강일치: dRel<=30m, 영상 확률>=0.8, 종거리 차이<=max(3m,dRel*0.2), 횡거리 차이<=2m, 속도 차이<=3m/s. 이때 경로 잔여 횡거리 2m까지 허용합니다. 일반 영상 일치보다 종거리·속도 조건을 강화하면서 차량 반사점과 영상 중심의 횡방향 차이를 허용합니다.
- 이 보완도 서로 다른 레이더 관측 3개 이상 및 0.15초 이상의 연속성 조건을 지켜야 합니다. 일반 불연속 트랙은 재성숙을 기다리며, 6절의 기존 측면 트랙 예외에 한해 관측 이력이 유지될 수 있습니다.
- FF의 횡위치를 0으로 고정하지 않으며, 측면 거리80m/횡거리5.4m 및 경계 검사를 유지합니다. radarState/leadsCenter는 추가하지 않았고 차로폭·로드엣지 여유도 변경하지 않았습니다.

### yaw rate 표시 보정 제거

사용자 요청으로 `card`의 표시용 `livePose` 구독, yaw 추출 함수, `apply()` 추가 인자 및 CS 전달 필드를 제거했습니다. `card.py`와 `interfaces.py`는 이번 표시용 변경 이전 상태로 복원됐습니다. 기존 차량 제어의 자세 처리에는 변경이 없습니다.

경계 판정의 회전 좌표 적분, 속도 회전 보정, yaw 크기에 따른 이동/정지 허용 보류도 제거했습니다. 이동 확인에는 원시 `vLead`/`yvRel`과 `(dRel + stop_distance, yRel)`의 지속 변화를 사용합니다. `stop_distance`는 기존 접근/정차 표시가 사용하는 자차 이동거리이며 회전 보상 좌표가 아닙니다. 회전 중 반사점 오차를 보정한다고 주장하지 않습니다.

실제 경계 근접 정지점 제외, 경계 정보 부족만으로 차단하지 않는 정책, 정차 중 지속 횡이동 점의 저장 제외 및 기존 차량 유지 조건은 남깁니다. yaw 전용 테스트를 제거하고 나머지 표시 회귀 테스트 131개가 통과했습니다. 커밋·푸시·NAS 배포는 하지 않았습니다.

제거 후 356/358/38a/주행로그 및 엣지케이스를 재생했습니다. 38a10~11 RF, 358의 두 정차 유지 창, 35f5의 전체 표시 값이 보존됐습니다. 395--7 횡단 저장 잔상과 기존393--1/356--1 경계점 저장 제외도 유지됩니다. yaw 조건 제거가 출력상 완전히 무영향인 것은 아닙니다. 306 LF 전체에서8샘플 증가했고, 356에서FF10샘플/LF9샘플 증가 및FF1샘플 감소,358에서LF8샘플 증가,38a16에서FF3샘플 증가했습니다. 이 짧은 변화들을 모두 올바른 차량 검출이라고 판정하지 않으며 기존 회전 중 깜빡임은 미해결입니다. 35f의 표시 유무는 전 샘플 동일합니다.
