# CCNC 계기판 표시 기술 안내

현재 CCNC 표시 구조와 테스트 실행 방법을 정리합니다. 사용자용 기능 설명은 [한국어 설정 안내](user/ko/settings.md#ccnc-display)와 [영어 설정 안내](user/en/settings.md#ccnc-display)에 있습니다. 개발 과정의 수치·중간 구현·로그 재생 기록은 [검증 이력](ccnc_validation_history.md)에 보존합니다.

## 적용 범위

세 가지 표시 설정은 각각 독립적으로 켜고 끌 수 있으며 기본값은 모두 꺼짐입니다. 차선 색상과 차선 애니메이션은 CCNC 표시 경로에서 적용되고, 전방 레이더 차량 표시는 HDA1에만 적용됩니다. HDA2에서는 레이더 차량 표시 옵션을 켜도 해당 경로를 실행하지 않습니다.

| 설정 | 표시 범위 | 상태 갱신 |
|---|---|---|
| `CcncLaneColor` | 주행 기어에서 가감속·주행 모드에 따른 강조 색상, 속도에 따른 강조 길이 | 색상 상태와 주행 모드 캐시 |
| `CcncModelLanes` | 차선 곡률·위치, 차선 변경 강조·아이콘·전환, 속도 안내와 조향 보조 아이콘 | 차선 필터·전환 상태·속도 안내 타이머 |
| `CcncRadarVehicles` | HDA1 전방·측면 차량 표시와 정차 시 표시 유지 | 차량 선택·유지·위치 필터 |

설정은 약 1초 주기로 갱신합니다. 색상 또는 차선 옵션의 전환은 레이더 차량 유지 상태를 초기화하지 않습니다. 차량 옵션 전환 시에는 차량 상태를 초기화합니다. 트레일러 관련 차선 변경 제한은 표시 효과보다 우선합니다.

## 코드와 입력

- [hyundaicanfd.py](../opendbc_repo/opendbc/car/hyundai/hyundaicanfd.py): 기본 CAN 메시지 생성, 설정 읽기, 선택한 표시 효과 호출, 최종 차량 아이콘 값 변환.
- [hyundaicanfd_ccnc_extension.py](../opendbc_repo/opendbc/car/hyundai/hyundaicanfd_ccnc_extension.py): 선택적 차선·색상 처리, `_CcncRadarLaneSelector`, `_CcncRadarDisplayTracker`, 차량 위치 필터.
- [card.py](../openpilot/selfdrive/car/card.py): `modelV2`, `radarState`, `liveTracks` 수신 상태 확인 및 전달.
- [interfaces.py](../opendbc_repo/opendbc/car/interfaces.py): 전달받은 입력을 CarState에 연결.
- [carstate.py](../opendbc_repo/opendbc/car/hyundai/carstate.py): 표시용 입력 초기화.

`card`는 다른 프로세스가 발행한 `liveTracks`를 구독합니다. 메시지가 valid/alive이고 수신 시각 기준 나이가 0 이상 150ms 미만일 때만 전달합니다. 유효하고 살아 있는 `radarState`도 함께 전달하며, 기본 차량 표시는 이를 사용할 수 있습니다. HDA1 레이더 차량 표시를 켜면 해당 표시 결과를 기본 선행차 표시로 덮어쓰지 않습니다.

## 확장 코드 정리

확장 모듈은 `hyundaicanfd_ccnc_extension.py`, 호출명은 `ccnc_extension`입니다. 테스트에서 확장 표시를 일괄 지정하는 인자는 `extended_ccnc`로 통일했습니다. 전방 레이더 차량 표시는 HDA1 전용이며, 기존 HDA2 차선·색상 효과는 계속 사용합니다.

호출되지 않는 필터의 `fill()` 함수, 전용 위치 필터의 미사용 필드, 차선 함수의 미사용 인자, 중복 초기화와 조건 검사를 제거했습니다. 차선 옵션이 꺼진 경우 먼저 반환하도록 흐름을 단순화했습니다. 차량 선택·추적 클래스는 구문 트리 비교로 변경이 없음을 확인했습니다. 일반 필터의 가변 계수 경로는 전용 필터의 동등성 시험에 사용하므로 유지합니다.

정리 후 전용 테스트 419개가 통과했습니다. Windows에서는 전체 저장소 스키마를 임시 ASCII 경로에서 읽고 실제 Params 접근을 차단한 시험 환경을 사용했습니다. 변경 전후에 세 설정의 모든 조합, HDA1/HDA2, 차선 소실·변경, 트레일러 제한을 포함한 640회의 연속 메시지 생성 결과가 일치했습니다. 합성 입력의 비교이며 실차 검증은 아닙니다.

## 전방 차량 표시 흐름

1. 전방 레이더 출처의 유한한 좌표·속도를 가진 후보를 확인합니다. 순정 SCC와 코너 레이더 점을 이 후보에 섞지 않습니다.
2. 새 레이더 관측의 연속성과 차선·경로 정보를 확인합니다. 같은 발행 데이터를 반복 처리한 횟수로 새 관측 수를 늘리지 않습니다.
3. 차선 기준으로 정면·좌측·우측 후보를 분류하고 곡률을 보정합니다. 측면 후보에는 거리·속도·차로폭·경계 조건을 적용합니다.
4. 차선 정보가 부족하면 영상 선행차와 모델 경로를 이용해 정면 후보를 보완합니다. 영상 정보만으로 레이더 차량을 새로 만들지는 않습니다.
5. 각 슬롯에 최대 한 대를 선택하고 트랙별 필터를 거쳐 계기판에 표시합니다. 차량 아이콘 변환은 기본·추가 표시 처리 이후에 적용합니다.

측면 후보의 원시 종거리 상한은 80m입니다. 연속 관측되는 기존 측면 차량은 차선이 잠시 사라졌을 때 마지막 유효 차선 정보를 최대 2초 또는 자차 이동 30m까지 사용할 수 있습니다. 관측이 끊기거나 대상이 바뀌면 이 연속 표시가 끝납니다. 정차 유지와 경계 근접 정지점 제외는 별도 조건이며, 모든 정지 반사점을 차량으로 유지하지 않습니다.

차량 선택·표시 필터는 CCNC 표시 전용입니다. 원본 레이더 점이나 주행 제어용 선행차를 이 경로에서 수정하지 않습니다. 후측방 아이콘은 사각지대 감지 상태를 나타내며, 개별 차량의 측정 거리·정확한 위치를 나타내지 않습니다.

## 테스트 구성

기존 테스트는 병합한 `carrot-wip` 커밋 `d4fca67f20bc18ea543d93f9db5a7ac4fef66f91`의 내용을 유지합니다. 전용 실행기는 이 커밋의 카탈로그를 제공하며, CCNC·ALT2 버튼 원본 테스트에만 확장 옵션을 끈 호출을 적용합니다. 추가 설정은 별도 테스트에서 현재 카탈로그로 검증합니다.

| 테스트 | 목적 | 실행 대상 |
|---|---|---|
| 기존 `test_ccnc_cluster.py`, `test_ccnc_lead.py`, `test_ccnc_fault_filter.py`, `test_alt2_adas_buttons.py` | 기본 차량·선행차·알림 처리 | `vehicle` |
| `test_ccnc_extension.py` | 세 설정 조합, HDA2 제외, 상태 갱신, 실제 CAN 포장 | `vehicle` |
| `tools/ccnc/test_radar_display.py` | 경계·연속성·정차 유지·위치 필터 회귀 | `display` |
| 기존 Wiki 테스트 | 공통 기준 카탈로그의 생성·검증 | `docs` |
| `test_ccnc_catalog.py` | 현재 카탈로그의 추가 설정·다국어 설명·Wiki 생성·검증 보고서 | `docs` |

저장소 루트에서 실행합니다. Python, pytest, NumPy가 필요합니다. `vehicle`과 `all`은 현재 저장소의 CAN·cereal·Params 의존성을 준비한 개발 환경이 필요합니다.

```sh
python tools/ccnc/run_tests.py docs
python tools/ccnc/run_tests.py display
python tools/ccnc/run_tests.py vehicle
# 위 세 묶음을 함께 실행
python tools/ccnc/run_tests.py all
```

전용 실행기는 [pytest_plugin.py](../tools/ccnc/pytest_plugin.py)를 명시적으로 적용합니다. 기존 Wiki 테스트에만 Git에서 꺼낸 공통 기준 카탈로그를 제공하고, 기존 차량·선행차 테스트에만 추가 표시 옵션을 끈 호출을 제공합니다. 원본 테스트의 검증문이나 제품 동작은 바꾸지 않습니다. 새 CCNC 테스트는 현재 카탈로그와 실제 추가 표시 경로를 검사합니다. 얕은 체크아웃이라 기준 커밋이 없으면 해당 커밋을 먼저 받아야 합니다.

기존 Wiki 테스트를 현재 카탈로그에 직접 실행하면 고정된 설정 개수와 맞지 않습니다. 이 브랜치에서는 위 전용 실행기를 사용합니다. 기존 전체 저장소 테스트 환경을 대체하는 실행기는 아닙니다.

## 문서와 Wiki

설정 요약의 원본은 [설정 카탈로그](../openpilot/selfdrive/carrot_settings.json)입니다. 한국어·영어·중국어 설명이 Wiki 생성기의 자동 설명에 반영됩니다. 사용자 설명에는 코드 식별자·브랜치명·개발 및 배포 이력을 넣지 않습니다.

공개 Wiki 게시 워크플로는 `carrot-wip` 카탈로그를 기준으로 합니다. 이 브랜치의 설정을 공개 Wiki에 등록하기 위해 게시 대상을 바꾸거나 공통 브랜치로 기능을 옮기지 않습니다. 전용 테스트는 이 브랜치 카탈로그의 생성·검증 결과를 확인합니다.

Road Viewer는 별도 기능이며 [업로드 테스트 안내](../openpilot/selfdrive/carrot/server/road_viewer/TESTING.md)에 준비 환경, 로컬 통합 시험, 실제 장치 확인 절차를 정리합니다.

## 검증 한계

합성 테스트와 기록 입력 재생은 실제 차량 계기판의 표시 품질이나 주행 부하를 검증하지 않습니다. 모델 경계 오차·레이더 반사점·추적 식별자 재사용으로 누락이나 오표시가 남을 수 있습니다. 차량 표시 예외 처리에는 고정된 대체 표시도 있어 오류 시 항상 표시가 꺼지는 것은 아닙니다. 이번 정리는 문서·설정 설명·테스트 분리와 확장 코드의 이름·내부 구조 정리에 한정하며 표시 판정이나 주행 제어 정책을 변경하지 않습니다.
