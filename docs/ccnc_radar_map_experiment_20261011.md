# CCNC 독립 레이더 지도 실험

현재 후속 구현은 아래의 **근거리 지도·연산 개선** 절을 따릅니다. 앞부분의 100m 독립 선택기와 실패 수치는 첫 실험 기록입니다. 기존 차량 실행 코드는 계속 보존합니다.

사용자가 기존 코드를 보존한 채 `hyundaicanfd_ccnc_radar_map.py`에서 지도 기반 감지를 진행하도록 요청했습니다. 비교 기준은 `b06bef4b`의 `hyundaicanfd_ccnc_extension.py`이며 소스 SHA256 접두사는 `d473d0fb4bd7`입니다. 기존 실행 모듈은 수정하지 않았습니다. 새 모듈은 독립적인 시험 구현이며 현재 차량 컨트롤러에서 호출하지 않습니다. 커밋·푸시·설정 추가·차량 설치는 하지 않았습니다.

## 구현과 범위

`opendbc_repo/opendbc/car/hyundai/hyundaicanfd_ccnc_radar_map.py`의 `CcncRadarMap.update()`는 원본 `liveTracks`, 모델, 단조 시각과 자차 속도를 받습니다. 레이더·모델 관측 시각을 별도로 전달하며 현재 입력보다 늦지 않아야 합니다. `display_values()`는 호출자가 전달한 CAN 값 사본의 FF/LF/RF 거리·횡위치·검출 필드만 갱신합니다. 기존 후보 선택·구조물 판정·위치 보정 클래스를 호출하지 않습니다. 원본 레이더·모델·주행 제어는 수정하지 않습니다.

- 전방 레이더의 유효 실측점들을 자체 객체 ID로 관리합니다. 레이더 ID는 대응의 보조 정보입니다. 예측 위치 주변 0.5m가 기본 연결 범위이고 같은 ID에는 오차 지표에 따른 제한된 여유를 줍니다. 일대일 연결, 속도 차이 검사와 모호한 ID 변경의 연결 거절을 적용합니다.
- 자차 속도·yaw를 적분한 로컬 좌표에 객체와 차선을 저장합니다. 관측 시각의 자차 자세로 실측을 변환하고 현재 시각까지 물체 속도로 예측합니다. 모델 yaw와 레이더 횡좌표의 부호 차이를 반영합니다. 새 측정 위치와 예측 위치를 가중 평균하며, 미검출·예측·동일 발행 재처리는 관측 근거를 늘리지 않습니다.
- 존재 점수, 차량 근거 점수와 위치 오차 지표를 분리합니다. 이 값들은 보정된 확률·공분산이 아닙니다. 여러 위치 관측의 일관된 이동이나 강한 비전 일치가 차량 근거가 됩니다. 이동 후 멈춘 차량의 이력을 유지합니다. 차로 내부라는 이유만으로 차량을 확정하지 않으며, 처음부터 정지한 측면 물체는 미확정으로 남을 수 있습니다.
- 정지점은 원래 세계 위치에 유지합니다. 자차가 멈춘 뒤 과거 상대속도로 점을 계속 뒤로 이동시키지 않습니다. 이동 객체는 추정 속도로 예측하고 미관측 중 위치 오차 지표를 키워 표시 허용을 제한합니다. 기억 보관과 표시 허용은 별개입니다.
- 기본 지도 범위는 뒤 5m~앞 100m, 좌우 12m이고 최대 객체 수는 256개입니다. 개별 객체에 일률적인 생존 시간은 적용하지 않습니다. 용량 초과 시 미확정·근거 부족 객체를 우선 정리하되 현재 관측에서 갱신 예정인 객체는 보호합니다. 시간 역전·250ms 초과 처리 단절·자차 자세 불명·후진은 좌표계 연속성 상실로 초기화합니다.
- 차선은 자차 이동을 보상해 저장하고 이전에 관측했던 뒤쪽 일부도 유지합니다. 현재 차선 확률과 연속성을 확인하며, 약한 새 관측은 저장 차선의 신뢰도를 낮춥니다. 차로 중앙에 가까운 대표점을 우선하되 가까운 두 객체의 ID를 합치지는 않습니다.
- 반복 관측된 정지점의 근접 배열로 최대 24개 벽을 구성합니다. 최초 배열은 세 점 이상·4m 이상, 연결 간격 0.6~3m와 직선 잔차 검사를 사용합니다. 벽당 최대 16개 근거점을 기억합니다. 차량 이동·비전 근거가 있거나 신뢰하는 차로 내부인 점은 새 벽의 근거에서 제외합니다. 기존 벽의 근거가 이동하면 벽을 취소합니다.
- 확정한 벽 밖으로 확장되는 차선은 표시용 차로 분류에서 벽 위치로 제한합니다. 이 결과를 새 벽 확인 근거에 재사용하지 않으며 원본 모델 차선을 바꾸지 않습니다. 벽은 물리적 벽임이 인증된 결과가 아니라 이 규칙에 따른 구조물 가설입니다.
- 대향 이동 객체도 지도에는 기록하지만 같은 방향의 좌우 표시에서는 제외합니다. 음수 종거리의 객체는 현재 LF/FF/RF CAN 거리로 출력하지 않습니다. 지도에 뒤쪽 점을 저장한다고 계기판에서 실제 후방 좌표를 표시할 수 있다는 뜻은 아닙니다.

관측 네 번·150ms 이상의 위치 변화, 일관된 이동 0.35m/s 초과, 정지 확인 300ms, 연결·직선성·오차 증가율 등은 초기 시험값입니다. 최적값을 로그에서 학습하거나 실제 센서 오차로 보정한 수치가 아닙니다. 반사점의 지속 이동과 실제 객체의 이동, 보행자와 차량을 완전히 구별하지 못합니다. 앞선 구조물 지도의 실패를 해결한 완성본이라고 취급하지 않습니다.

## 재현

독립 검사:

```text
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -c tools/ccnc/pytest.ini --noconftest -q tools/ccnc/test_radar_map.py
```

`tools/ccnc/replay_radar_map.py`는 기존 위치 보정 미사용·사용 두 기준과 새 지도 후보를 같은 입력에서 비교합니다. 기존 두 설정은 새 지도를 켜고 끄는 기능이 아닙니다. 매니페스트는 `entries` 안에 `name`, `path`, `sha256`을 가진 로컬 rlog 목록이며 인접한 구간은 상태를 이어 재생합니다. 소스와 입력 해시, 입력 미준비 제외 횟수, 슬롯별 표시 추가·삭제, 처리 시간과 지도 크기를 기록합니다. `--maps`는 지도 검토용 스냅샷을 추가하고 `--summary-only --repeat 3`은 프레임 직렬화 없이 반복 시간을 측정합니다.

```text
python tools/ccnc/replay_radar_map.py --manifest PRIVATE_MANIFEST.json --output PRIVATE_OUTPUT --maps
```

Windows 검증에서는 기존 전체 cereal 스키마·Params 대체 부트스트랩을 사용했습니다. 이 환경 준비 코드, 원본 입력 목록, 단계별 실패와 최종 지도·영상은 비공개 분석 보관소에 보존합니다. 표시 필드 변화나 검출 감소 횟수 자체는 정확도 향상의 증거가 아닙니다.

- 근거리 15m 이내의 같은 레이더 ID는 기본 0.85m에 오차 지표의 일부를 더해 최대 1.2m까지 연결합니다. 다른 ID는 기존 0.5m와 모호성 검사를 유지합니다. 같은 ID도 속도 차이·거리·일대일 연결 조건을 통과해야 하므로 재사용된 ID를 무조건 같은 물체로 합치지 않습니다.

- 새 벽은 기억된 정지 이웃도 이용하지만 실제 새 측정 두 개 이상의 뒷받침이 있어야 합니다. 예측점만으로 새 벽을 만들지 않습니다. 벽 연결 과정에서 너무 가까운 점이나 배열에서 벗어난 점 하나 때문에 탐색 전체를 중단하지 않습니다.
- 사용자 후속 지시에 따라, 같은 쪽의 인접한 두 벽 사이에 실제 관측한 정지점이 있고 방향·직선성이 맞으면 두 벽을 연결합니다. 양끝 벽의 점 간격을 기준으로 연결 허용 간격을 3~6m 안에서 조정합니다. 중간 점이 없거나 이동 중인 점만 있거나 방향이 맞지 않으면 연결하지 않습니다. 모든 점을 서로 비교하는 방식이 아니라 벽을 순서대로 정렬한 뒤 이웃 벽을 확인합니다.
- 자차 회전의 삼각함수와 객체의 현재 상대 좌표를 재사용합니다. 차선은 근거리 보간에 필요한 부분만 보관하고, 같은 배열의 모든 접두부를 반복해서 벽으로 만드는 계산을 줄입니다. 차량 조건이 안 되는 객체의 차로 분류를 늦추고, 기존 검출을 함께 쓰는 경로에서는 독립 후보 선택을 생략합니다.

| `structure_suppresses()` | 공간 검색을 지도 분류 조회로 대체 | 기존 이동 확인·비전·정차 기억 보호 정책은 명시적으로 이관. 새 `refine_existing()`는 이 정책 전체와 동일하지 않음 |
| `update_boundary_admission()` | 당장은 유지, 이후 일부 공통화 | 이동 확인, 단독 경계점 차단, 정차 기억 취소, 대표점 선택의 근거를 함께 제공. 벽이 없는 단독점도 처리하므로 지도 벽만으로 대체 불가 |
| `_CcncTemporalTracks` / `observe()` | 추적 데이터 공유는 후속 후보, 즉시 제거하지 않음 | 기존 좌표·속도 이상치 거부, 300ms 예측, ID 재연결과 후보 유지 조건을 보존해야 함. 새 지도 위치 평균은 같은 기능이 아님 |
| 차선 읽기·검증·보간 | 원본 배열/유효성의 공유 후보 | 기존은 현재 차선·도로 경계·먼 차량을 사용하고 지도는 자차 보정한 과거 차선을 보관. 신뢰도·좌표 시각이 다른 최종 차로 판정을 무조건 공유하지 않음 |
| 후보 선택·FF 경로/비전 보완·대표점 선택 | 기존 유지 | 새 지도 독립 선택은 이미 알려진 실제 RF를 잃은 이력이 있음. 30m 밖 기존 표시도 필요 |
| 위치 보정·슬롯 안정화·정차/감속 기억·교차 차량 판별 | 기존 유지 | 구조물 분류와 별개인 표시 정책. 지도 객체가 남아 있다는 사실만으로 계속 차량을 표시할 근거가 되지 않음 |

현재 결합은 기존 출력과 정차 기억을 모두 계산한 뒤 지도에서 `DETECT`만 내립니다. 그 때문에 억제할 후보의 위치 보정까지 수행하며, 그 후보를 숨긴 뒤 같은 차로의 다음 적격 차량을 다시 선택하지 않습니다. 통합 시에는 **현재 관측 → 지도 갱신/구조물 분류 → 기존 적격 후보 선택 → 위치 보정·기억·출력** 순서가 적절합니다. 구조물 거절 정보는 일반 후보뿐 아니라 FF 경로 보완, 차로 간 이동 보완, `temporal.select()`의 유지 경로와 신규 정차 기억 등록에도 전달해야 합니다. 기존에 확정된 차량 기억의 보호는 별도로 유지합니다. 순서를 바꾸면 다음 차량이 새로 표시될 수 있으므로 지금의 단순 후처리와 출력 동등성을 가정하지 않습니다.

기존 temporal 추적의 `trackId`는 재연결·ID 재사용에 따라 원본 레이더 ID와 달라지고 `ccnc_source_id`에 현재 원본 ID를 따로 보관합니다. 지도는 원본 ID를 `source`로 기록합니다. 현재 후처리의 ID 불일치는 대체로 판정을 건너뛰는 방향이지만, 기존 구조물 판단을 제거하려면 원본 ID·추적 세대·측정 시각·좌표를 확인한 연결을 먼저 마련해야 합니다. 예측점을 새 관측처럼 지도에 넣어 벽 근거를 늘려서는 안 됩니다.

기존 구조물 코드는 50m, 기존 측면 후보는 80m까지 처리합니다. 새 지도 30m를 유지하면서 기존 구조물 처리를 전부 삭제하는 것은 범위 축소입니다. 우선 근거리 역할을 이관하고 원거리 정책은 보존하는 편이 타당합니다. 단순히 구형 지도에서 0~30m 점을 빼는 것도 30m 경계를 가로지르는 배열 근거를 잃으므로 동등하지 않습니다. 최종 단일 지도화 여부는 이 범위와 경계 전환을 별도 비교한 뒤 결정해야 합니다.

### 함수별 비용 확인

기존 다섯 구간(356/2, 358/3, 395/6, c1/21, db/48), 각 1회·총 5,997개 유효 송신에서 현재 코드를 `cProfile`로 관찰했습니다. 위치 보정 사용/미사용 모듈은 서로 다른 가상 소스 이름으로 컴파일하여 통계를 분리했습니다. 첫 실행은 같은 파일명·행번호로 통계가 겹칠 수 있어 정량 해석에서 제외하고 분리 실행만 사용했습니다.

위치 보정 사용 경로의 `update_vehicles()` 누적 8.649초 중 `update_structure_regions()`가 2.147초(약 24.8%)이며, 그 안에 `update_stationary_map()` 1.509초가 포함됩니다. 두 시간을 더하면 중복 집계입니다. temporal 관측 처리는 2.214초로 비용이 크지만 제거 시 위치 튐 방지가 사라질 수 있어 우선 삭제 대상이 아닙니다. 새 지도에서도 `update()` 5.274초 중 `_update_lanes()` 1.822초(약 34.6%)가 관찰되어, 벽 연결의 산술보다 차선 자료 처리·좌표 변환의 중복을 줄이는 쪽도 검토 가치가 있습니다.

이 수치는 계측 오버헤드가 들어간 함수별 누적 시간이며, 앞 절의 비계측 ms 수치와 비교하거나 삭제 후 절감률로 환산하지 않습니다. 실제로 덜어낼 수 있는 범위, 이관 비용과 검출 변화는 아직 측정하지 않았습니다. 이번에는 새로운 제거안의 130구간 재검증이나 차량 검증을 수행한 것이 아닙니다. 프로파일·소스 식별·재현 스크립트는 비공개 `.analysis/archive/2026-10-12/ccnc-map-overlap`에 보관합니다.

## 2026-10-12 후보 선택 전 통합 구현

후속 적용 지시에 따라 새 지도 모듈에 `integrated_tracker()`를 추가했습니다. 보존된 기존 실행 모듈의 추적기를 상속하여 관측·차량 허용·후보 선택·위치 보정·정차 기억을 재사용합니다. 기존 모듈 파일과 실차 호출 경로는 변경하지 않습니다. 오프라인 재생의 `--integrated`가 새 경로를 실행하며, `--hybrid`는 직전의 출력 후처리 비교용으로 남습니다. 실차 설정 스위치를 추가한 것이 아닙니다.

근거리의 기존 구조물 판단 전체를 처음부터 제거한 시험은 다섯 구간에서 기존에 없던 LF를 각각 19/6/17/31/43회 만들었습니다. 기존의 동시 배열 검사가 지도에서 아직 정지점으로 확정하지 못한 반사점도 억제하고 있었기 때문입니다. 이 버전은 채택하지 않았습니다. 최종 구현은 다음과 같이 역할을 나눕니다.

- 기존의 세 점/4m 동시 배열 검사와 고정 배열 유지 기능은 보완 근거로 남깁니다. 근거리 정지점 이력과 이 검사까지 한꺼번에 제거하지 않습니다.
- 기존 정지점 메모리에 전방 15m 미만의 새 점을 중복 등록하지 않습니다. 15~30m는 원거리 배열의 근거를 위한 겹침 범위이며 30~50m의 기존 처리 범위는 남깁니다. 이미 원거리에서 등록한 점은 기존 만료 조건으로 정리합니다. 따라서 모든 중복 메모리를 없앤 구현은 아닙니다. 이 겹침은 모든 장거리·비동시 배열의 동등성을 수학적으로 보장하는 한계가 아니며, 범위 경계 검사는 제한된 합성 입력과 아래 재생에 한정됩니다.
- 지도를 갱신하고 기존 배열 근거도 한 번 갱신한 뒤 FF 허용과 LF/RF 대표점 선택에 구조물 판정을 전달합니다. 구조물을 먼저 제외하므로 해당 점의 위치 보정을 생략할 수 있습니다. 다른 적격 차량을 선택할 때에는 기존의 이동 확인·비전·확정 기억 근거가 있는 대상을 우선합니다. 구조물 하나를 제거했다고 다음 미확정 정지점을 곧바로 정차 기억으로 승격시키지 않습니다. 구조물에 가려지지 않은 일반 정차 차량의 기존 허용·기억은 유지합니다.
- FF 경로 보완, 차로 간 이동 보완과 temporal 후보 유지 경로에도 같은 거절 ID를 전달합니다. 원본 레이더 ID인 `ccnc_source_id`와 실제 측정 좌표를 확인하고, 재사용된 추적 ID의 세대가 다르면 이전 거절 이력을 잇지 않습니다. 원본 코드가 이미 허용한 이동 차량, 강한 비전 근거와 기존 정차/감속 기억의 보호는 유지합니다.
- 새 관측으로 확인한 구조물 판정은 기존 예측 유지 시간 안에서만 미검출 구간에 전달합니다. 예측점으로 관측 시각이나 벽 근거를 갱신하지 않습니다. 지도 입력이 무효이면 기존 배열 억제 조회를 우회하지 않습니다.
- 확인된 벽 끝에 새로 관측한 정지점이 정렬되면, 관측된 인접 간격 또는 그 두 배에 맞는 한 번의 누락 위치까지 연결합니다. 단일 대표 간격만 사용한 중간 버전은 서로 다른 간격의 배열을 놓쳐 c8/3에서 거짓 정차 기억을 만들었습니다. 최종 버전은 실제 인접 간격들을 사용하며 직선 오차 0.25m, 간격 오차 0.35m, 기존 간격 0.6~3m와 최대 16개 앵커 제한을 유지합니다. 미관측 위치에 점을 생성하지 않습니다. 기존 벽 근거가 있는 연장에서는 이후 차선이 넓어졌다는 이유만으로 연결을 거부하지 않습니다.
- 기존 추적기가 이미 검증한 차선 배열과 보간 캐시를 지도에서도 재사용합니다. 현재 차선과 지도에 기억한 차선의 의미는 합치지 않습니다. 같은 측정 시각의 회전 삼각함수를 재사용하며 거리의 `hypot` 계산은 유지합니다.

통합 경로에서도 처리 순서 변화로 후보 ID와 표시 이력이 달라질 수 있습니다. 기존 출력과의 차이는 모두 정확도 향상으로 해석하지 않습니다. 특히 395/6의 새 LF 후보 ID33은 기존 이동 허용 상태에 진입한 점입니다. 진단 재생에서 프레임 3634에 원본의 세 이동 창과 누적 0.5m 조건을 통과했고, 이번 통합이 그 보호를 유지하여 다른 구조물 제거 뒤 선택됐습니다. 영상에서는 분리대 주변으로 보이지만, 이 점을 임의로 거절하기 위해 기존 이동 차량 보호를 없애지는 않았습니다.

관련 검사 947개가 통과했습니다. 새 검사 18개는 다음 차량 선택, 구조물의 신규 정차 기억 방지, 일반 정차 차량 유지, 기존 네 종류 차량 보호, ID 재연결과 예측 만료, 미측정 패킷의 시각 증가로 거절 이력이 연장되지 않는 조건, 30m를 가로지르는 배열, 벽 간격 변화, 차선 캐시 동등성과 무효 입력을 포함합니다. 저장 로그와 차량 CPU/실제 응답에 대한 결과는 구별합니다.

현재 목록의 rlog 139개에서 동일 파일 9개를 제외한 130구간을 재생했습니다. 입력 준비 전 송신 2,203회를 제외한 152,695회가 비교 대상입니다. 각 구간의 기존 실행 코드 출력은 앞선 보관본과 같았습니다. 아래 수치는 기존 위치 보정을 사용하는 코드와 이번 통합을 비교한 **송신별 슬롯 변화 횟수**이며, 물체 개수나 정확도 점수가 아닙니다. 위치 변화는 양쪽 모두 표시 중일 때만 세었습니다.

### 발견 1: 레이더가 주는 이동 분류값

전방 레이더 트랙 메시지(0x3A5~)의 3번 바이트 비트 4..3(DBC 이름 `VALID2`)은 현재 쓰지 않는 값입니다. 12구간 원본 CAN에서:

- 도플러로 정지인 점의 94.4%가 값 1, 전진 이동인 점의 96.6%가 값 2, 대향 이동의 87.1%가 값 0입니다.
- 값 2는 고정됩니다. 트랙 내 전환은 1↔0, 1→2, 0→2, 2→0만 있고 2→1은 0건입니다. 자차 정지 중 움직이지 않는 대상 가운데 이전에 움직였던 트랙은 값 2가 1,599회, 값 1이 9회입니다. 즉 "움직였다가 멈춘 차"를 레이더가 기억해 줍니다.
- 사전 검토 구조물 장면의 선택점에는 값 2가 한 번도 없습니다(0 또는 1).
- 기존 코드의 30m 이내 측면 표시 중 약 76%가 값 2입니다.
- c1/23의 실제 차량은 값 0입니다(정지해 있다가 약 1m/s로 천천히 출발). 값 2만으로는 느린 출발 차량을 놓칩니다. 이 차량은 도플러 잔차 0.7m/s 초과가 26프레임 있어 도플러 증거로는 잡힙니다.

### 발견 2: 근거리 고방위각 점은 레이더가 관성 예측 중인 트랙

같은 메시지의 `VALID`(상태)와 `PROB`를 보면 값 2 차량은 97%가 상태 2·PROB 64 이상인데, 검토 구조물의 잔여 6회와 c1/23의 6프레임은 모두 상태 0/1/3 또는 낮은 PROB입니다. 거리 2m·방위각 50° 부근의 점은 대상 종류와 무관하게 레이더가 놓친 트랙을 자기 속도 추정으로 이어 가는 값으로 보입니다. 앞서 확인한 "보고 위치가 보고 속도의 적분만큼 밀리고 45° 이상에서 속도가 고정되는" 현상과 일치합니다. 신호 의미는 통계로 추정한 것이며 문서로 확인하지 않았습니다.

### 발견 3: 남는 문제는 한 번도 움직이지 않은 정지 물체

기존 코드의 30m 이내 측면 표시를 근거별로 나누면 레이더 값 2가 62,129회, 도플러 증거 6,302회, 기존 정차 기억 5,605회, 근거 없음 8,154회입니다. 검토 구조물 잔여 6회는 모두 "근거 없음"이고, 그 절반가량(자차 정지 중 4,329회)은 신호 대기 중 이미 서 있던 옆 차로 보이는 표시입니다. 이 둘은 이동 근거로는 원리적으로 구분되지 않으며, 위치·배열(벽) 근거가 필요한 범위는 이 약 10%입니다.

### 시험: 이동 허용에 레이더/도플러 증거 요구

기존 코드의 scratch 복사본에서 기존 이동 허용 조건에 "레이더 값 2 또는 도플러 잔차 0.7m/s 초과 5회"를 추가로 요구했습니다. 130구간에서 기존 코드 대비 LF 141/RF 19/FF 65회 제거, FF 9회 추가, 30m 밖 2회 제거, 검토 잔여는 6 그대로(잔여는 이동 허용이 아닌 정지 허용이므로), c1/23 6/6입니다. FF 변화(356/1 33회, 358/7 17회 제거)는 확인하지 않았습니다. 효과는 작고, 잘못된 이동 허용만 겨냥합니다.

차량 근거가 있는 기존 표시를 지도 단독이 놓친 22,368회의 사유는 차로 판정 불가 11,001, 지도에 객체 없음 4,578, 관측 부족 2,853, 범위 밖 근거 불일치 2,626, 다른 슬롯 판정 1,083, 기타 227회였습니다.

1. **차선 사용 기준.** 지도는 확률 0.3 이상인 차선이 양쪽에 있어야 차로를 인정했습니다. 기존 코드와 같게 맞췄습니다: 확률 0.1부터 사용, 옆 차로의 바깥 경계는 바깥 차선 또는 도로 경계(폭 1.8m 이상), 이동 차량은 바깥 여유 0.75m, 차선이 전혀 없으면 정면 1.2m 이내만 FF, 측면 표시는 80m까지. 확신 차로 안쪽 판정(0.6)은 그대로라 벽 후보에는 영향이 없습니다.
2. **정지 중 지도 초기화 버그.** 자차 속도가 음수면 지도를 초기화하는데, 정지 중 필터된 속도가 미세한 음수로 읽혀 매 프레임 지도가 지워졌습니다. 신호 대기 중 바로 앞 차(자차 정지, 5m 이내, 레이더 분류 2) 약 4,900회가 이 때문에 누락됐습니다. −0.5m/s 미만에서만 초기화하고 그 사이는 0으로 처리합니다.
3. **먼 차량의 횡 한계.** 커브에서 먼 차량은 자차 축에서 12m 넘게 벗어나 지도에 들어오지 못했습니다. 지도 범위 밖 차량 후보는 횡 40m까지 받습니다.

지도 단독이 추가하던 레이더 분류 2 표시 14,400회는 대부분 60m 밖 옆 차로 차량이었고, 기존 코드의 측면 80m 제한과의 정책 차이였습니다.
