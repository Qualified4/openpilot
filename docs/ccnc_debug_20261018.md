# Carrot Web CCNC Debug

`ccnc-hda1`의 Carrot Web **Tools → CCNC Debug**에서 미리보기를 연결한 뒤
차량/차선 그룹, 개별 슬롯/좌우 차선을 선택한다. 기본은 송신 OFF이며,
**실제 계기판 CAN 송신**을 켜면 기존 CCNC 출력에 선택한 표시 필드만 적용한다.
브라우저 상태의 `CAN TX`는 생성기가 오버라이드를 적용하고 있다는 응답이다.
계기판의 수신 확인이나 실제 화면 변화의 확인 응답은 아니다.

차량은 LF·FF·RF·LR·RR를 독립적으로 켠다. DETECT의 기본값은 6
(`WHITE TRUCK`)이고 0~31을 선택할 수 있다. 미문서화 DETECT는 구분한다.
그룹/슬롯 OFF는 그 필드의 기존 출력을 유지한다. 다른 그룹에는 영향을 주지 않는다.
기존 Ccnc 설정, Xiaoge, PP-LCNet 학습/차선 분류기에는 의존하지 않는다.

## DBC와 변환

기준은 `opendbc_repo/opendbc/dbc/hyundai_canfd_generated.dbc`다. DBC를
수정하지 않는다. 모든 편집은 실제 `CANPacker`로 인코딩하고 raw 값을 다시
읽어서 물리값이 일치하는지 검증한 뒤 송신용 lease를 갱신한다.
허용 범위 밖, NaN/Infinity, bool 대신 숫자, 0.1m 간격 밖의 값, 알 수 없는
키는 거부한다. 미리보기의 hex는 선택한 필드만 채운 예시이며 전송하지 않는다.

`CCNC_0x162`는 0x162, 32바이트다. 아래 bit는 DBC start bit다.
모든 거리/횡위치의 factor는 0.1, offset은 0이다.

| 슬롯 | DETECT bit/폭 | DISTANCE bit/폭 | 거리(m) | LATERAL bit/폭 | 횡위치(m) |
|---|---|---|---|---|---|
| LF | 112/5 | 117/11 | 0~204.7 | 128/7 | 0~12.7, 좌측 거리 |
| FF | 64/5 | 69/11 | 0~204.7 | 80/7 | -6.4~6.3, +우측 / -좌측 |
| RF | 136/5 | 141/11 | 0~204.7 | 152/7 | 0~12.7, 우측 거리 |
| LR | 163/5 | 175/8 Motorola | 0~25.5 | 176/7 | 0~12.7, 좌측 거리 |
| RR | 192/5 | 197/8 | 0~25.5 | 205/7 | 0~12.7, 우측 거리 |

나머지는 Intel이다. DBC의 횡위치 필드는 모두 unsigned다. 기존 생성기는
FF에 음수를 넣고 packer의 7비트 래핑을 사용하므로 FF에만 같은 관례를
명시적으로 적용한다. 예: FF -0.1m → raw127 → DBC unsigned 해석12.7,
계기판/기존 생성기 관례 해석 -0.1m. FF -6.4m → raw64, +6.3m → raw63.
측면 슬롯에 이 부호 해석을 적용하지 않는다. DBC 주석의 횡위치 상한127,
후방 거리 상한255는 factor를 적용한 실제 상한12.7m/25.5m와 다르다.

`ADRV_0x161`은 0x161, 32바이트다. 아래 필드의 factor=1, offset=0이다.

| 필드 | bit/폭 | UI 범위 |
|---|---|---|
| LANELINE_LEFT | 80/4 Intel | 1·2·4·6·8·10·14 |
| LANELINE_LEFT_POSITION | 84/6 Intel | 0~63 코드 |
| LANELINE_RIGHT | 90/4 Intel | 1·2·4·6·8·10·14 |
| LANELINE_RIGHT_POSITION | 94/6 Intel | 0~63 코드 |
| LANELINE_CURVATURE | 100/4 Intel | 0~15 코드, 좌우 공용 |
| LANELINE_CURVATURE_DIRECTION | 104/1 Motorola | 0/1, 좌우 공용 |

위치는 미터 단위의 DBC 신호가 아니다. 기존 생성기는 위치 코드에 미터×10
관례를 쓰지만, 디버그는 계기판의 실제 해석을 조사할 수 있도록 raw 코드를
표시한다. 위치 주석0~15는 실제6비트/기존생성기의30과 맞지 않고,
곡률 주석0~31도 실제4비트와 맞지 않는다. 비트 폭으로 범위를 제한한다.
방향0/1의 좌/우 표기는 기존 생성기 및 0x1ea의 방향 enum 관례이며,
0x161 자체에는 방향 `VAL_`이 없다.

색상/점선/실선은 별도 필드가 없다. 좌우 각각 `LANELINE_*` 표시 코드를
선택한다. DBC에 문서화된 값은1 HIDDEN,2 WHITE,4 ORANGE,6 GREEN이다.
8·10·14는 **미문서화**로 표시하며 색상/종류를 임의로 이름 붙이지 않는다.
좌우에 독립 곡률/방향 필드를 만들지 않고 공용 곡률 오버라이드를 별도로 켠다.
패널에서 실제 DBC의 bit/폭/부호/factor/endianness도 펼쳐 볼 수 있다.

## 송신과 복귀

기존 `create_ccnc_messages`의 CAMERA_SCC HDA1 경로, 20Hz 일정, RX 템플릿,
ECAN bus와 packer를 유지한다. 0x161의6개 LANELINE 필드와0x162의5슬롯×3개
필드만 allowlist에 있다. FF_ALT, 경고/진동, 배경, 카운터 등은 덮어쓰지 않는다.
바뀐 payload의 CRC는 기존 packer가 계산하고 Panda는 기존 RX 기반 경로에서
원본 RX 카운터를 유지한 채 CRC를 계산한다. CAN socket, PubMaster, 별도
송신 프로세스, 중복 프레임, 제어용 CAN 수정은 추가하지 않는다.

허용 조건은 유효한 CAN, standstill, vEgo/vEgoRaw/네 바퀴 속도 절댓값≤0.001m/s,
P 또는 브레이크를 밟은 N, 가속 페달 미입력, 제어 비활성화다.
0x161과0x162 모두 checksum/counter 검사를 통과한 RX timestamp가150ms 이내여야
한다. 별도 direct-TX 옵션이 켜진 차량에서는 RX 기반 전달 모드로 돌려야 디버그를
허용한다(해당 옵션을 자동 변경하지 않는다). HDA2, 트레일러, 사각지대/차선 이탈/운전자 경고 및 원본 ALERTS/SOUNDS/
BCA/VIBRATE 경고가 있으면 정상 출력을 사용하고 재활성화를 요구한다.

브라우저는150ms마다 값을 갱신한다. `/dev/shm`의 권한0600 임시 파일을
atomic replace하며600ms lease를 사용한다. 시동/디스크 Params에 저장하지 않는다.
동일 출처 웹소켓 한 개만 소유할 수 있고, OFF/연결 종료/서버 종료는 파일을
삭제한다. 브라우저 숨김, Tools 이탈, 패널 닫기, 전체 OFF도 연결을 닫는다.
서버 재시작은 남은 파일을 제거한다. 이동/통신 이상/만료/경고 후에는 같은
활성화 세션으로 다시 송신하지 못한다. 사용자가 송신을 끈 뒤 직접 다시 켜야 한다.

복귀는 다음 기존20Hz 생성 시점에 적용된다. 단절을 즉시 관측하지 못해도
600ms 만료가 적용된다. host 자체가 멈추면 기존 Panda150ms 캐시 만료가 원본
RX로 복귀시킨다. 물리적0ms 복귀나 실차 지연을 측정한 결과는 아니다.

## 검증 범위

자동 테스트는 슬롯별 raw/물리값 경계, FF 부호 래핑, LR Motorola 거리,
좌우 표시 코드/위치 및 공용 곡률, 잘못된 입력 거부, 그룹·슬롯 독립성,
정차/기어/페달/제어/RX/경고/만료/재활성화 조건을 확인한다.
실제 기존 생성기의 디버그 ON/OFF CAN 바이트를 비교하여 allowlist와 CRC
이외의 비트, 카운터, 메시지 개수/주소/bus/일정 및 원본 RX 사전이 보존되는지
검사한다. 웹소켓 테스트는 미리보기 무송신, 편집, OFF, 단절, 만료,
교차 출처 거부, 단일 소유권과 잘못된 편집 시 복귀를 확인한다.

실차 설치·계기판 관찰·도로 주행 검증은 수행하지 않았다. 미문서화 표시의
실제 색상/종류와 위치 코드의 화면 효과는 안전 조건하의 계기판 관찰 대상이다.
기존 운전/경고 동작의 실차 검증을 대신하지 않는다.
