# CCNC 차선 ROI·전체 로그 재학습·표시 정책 검증 — 2026-10-18

현재 연결된 시범 ONNX와 기본 OFF를 유지한다. **새 ROI 기반 대량 재학습과 신규 모델 승격은 보류 상태다.**
요청한 3m 시작 범위는 검수한 모든 프레임에서 화면 밖이었고, 근거리 도색·가림을 head별로 승인할 자료가 부족하다.
원거리 품질 문제를 그대로 둔 채 데이터를 확대하지 않았다. 새 표시 정책은 로그·미리보기에만 구현했으며 CAN·주행 제어·Xiaoge·기존 CcncModelLanes 동작은 변경하지 않았다.

## 조사 범위와 정답 상태

로컬 전체 파일은 27 route, 중복 제외 189 구간이다. rlog 204개/189 고유 구간, qcamera 177개/168 고유 구간, fcamera 24개를 확인했다.
두 화질이 함께 있는 구간은 6개이며, 중복 사본 24개는 SHA-256이 같았다. 188개 로그는 Sonata 2024 carParams를 직접 확인했고,
carParams가 빠진 35f/11은 같은 route·동일 장치의 다른 구간 carParams와 원본 해시를 근거로 별도 출처를 기록해 포함했다. 영상 없는 구간은 3개다.

전체 영상 229,872프레임을 디코딩하고, 고정 10초 샘플링 대신 전체 시간대의 정확히 동기화된 5Hz 후보 56,171개를 검사했다.

그림자·노출·노면 질감이 영향을 주는 Laplacian 분산은 보조 선명도 지표로만 저장했다. 광학 MTF나 압축 전 원본 선명도는 측정 불가다.

이는 warp/resize 왕복 차이이며 실제 카메라의 광학 손실이나 인식 정확도 개선율이 아니다. 이미 흐려진 원거리는 작은 MAE를 보여도 좋은 정보가 아니다.

인코딩된 같은 YUV 프레임을 NV12로 재배치한 경로와 PyAV RGB 경로의 차이도 ROI별로 저장했다.
실시간 camerad의 패딩·노출·색 행렬·압축 이전 NV12를 직접 수집한 비교가 아니므로 **실시간 입력 동등성은 검증하지 못했다**.
현재 실시간 경로는 카메라보다 최대 150ms 이전인 modelV2를 허용한다. 이번 오프라인 정답 후보의 정확한 EOF 매칭과 다른 조건이며 실제 장치의 정렬 오차는 검증하지 못했다.

## 새 표시 정책: 미리보기·로그 전용

종류와 색상을 별도로 저장·만료하며 필요한 두 head가 모두 확정되어야 표시한다. 흰색만 보고 실선을 만들거나, 종류 갱신만으로 만료된 색상을 유지하지 않는다.
여기서 확정은 신뢰도 0.85와 반복 관측을 통과한 실험적 상태명이다. softmax·마스크 점수는 보정되지 않았으며 packet의 classificationValidated도 false다.
흰 실선 기본값은 2, 확실한 노란 경계는 주황 실선 후보 4, 흰 점선 후보는 8, 미확정 만료 후 숨김 후보는 1이다.
노란 점선의 경우 원래 분류는 보존하되 요청된 주황 실선 표현으로의 렌더링 대체를 별도 기록한다.

- 각 head는 신선하고 동일한 결과 2회를 받아 확정/전환한다. 5Hz 목표에서 통상 0.2초이며 실기 측정값은 아니다.
- 흰 점선은 추가로 3개 이상의 도색 구간과 2개 이상의 내부 공백을 요구한다. 선행차 가림이 있는 입력을 새로운 점선 증거로 사용하지 않는다.
- 관측 부족·가림·실패·지연 때 마지막 실제 증거부터 최대 0.5초만 유지한 뒤 숨김 후보가 된다. 보류/유지 결과는 유효기간을 연장하지 않는다.
- 차선 변경·경계 추적 상실·경계 도약·시계 역행은 표시 이력을 초기화한다. 좌우 및 타입/색상 이력은 독립이다.
- 기존 차선 이탈·사각지대·차선 경고는 분류보다 우선한다. 기존 코드와 점멸 숨김 단계도 복사본에서 보존한다. 실제 baseline을 모르면 경고 코드를 만들어 내지 않는다.
- `recognised_yellow_boundary`와 `existing_warning_priority`를 구분한다. 기존 경고 주황을 노란 경계 인식으로 평가하지 않는다.
- daemon은 carControl·carState를 읽어 경고 문맥을 기록할 뿐 제어·CAN을 수정하지 않는다. 경고 문맥이 없으면 새 미리보기 코드를 차단한다.

| 값 | 저장소에서 확인한 의미 | 현재 취급 |
| --- | --- | --- |
| 1 | DBC HIDDEN | 숨김 미리보기 후보. Sonata 실제 지원 미검증 |
| 2 | DBC WHITE, 기존 기본 차선 표시 | 확정 흰 실선 기본 미리보기. 새 실차 검증 아님 |
| 4 | DBC ORANGE, 기존 경고에 사용 | 노란 경계 후보와 경고 사유를 분리. 실제 송신 변경 없음 |
| 8 | DBC 라벨 없음 | 이전 초안의 점선 가설, 미리보기만. Sonata 실제 점선 지원 미검증 |

DBC 근거는 `opendbc_repo/opendbc/dbc/generator/hyundai/hyundai_canfd.dbc`의 VAL_ 353이다. 비트 조합의 의미를 임의 추정하지 않았다.
실제 cluster에는 이 정책을 연결하지 않았다. `CcncModelLanes`, 옵션 OFF, Xiaoge와 기존 경고 CAN 출력은 그대로다.

## 표시 정책 오류·미확정·전환

추가 dense 평가: 3ed/6의 0.5~4.5초와 3ed/68의 39~43초를 f/q 각각 5Hz로 추출한 168개 ROI다.
HD 문맥과 각 화질 strip을 확인해 142개를 승인했고, 터널 진입 전 점선→실선 전환이 긴 ROI 안에 섞인 26개는 타입 정답을 부여하지 않았다.
두 짧은 구간과 화질 변형의 연속 프레임이므로 독립적인 142개 도로 장면이 아니다. 경고 baseline 없는 no-warning 미리보기이며 경고 우선순위는 별도 단위 테스트로 검증했다.

| 방식 | 검수 중 표시 확정 | 확정 표시 정확도 | 전체 미확정/숨김률 | False Dashed/점선 표시 | 잘못된 주황/주황 표시 | 표시 전환(160 인접쌍) |
| --- | --- | --- | --- | --- | --- | --- |
| onnx | 11/142 | 100.00% | 93.45% | 0/4 | 0/0 | 4 |
| opencv | 42/142 | 83.33% | 72.02% | 7/29 | 0/13 | 10 |

PP-LCNet의 100%는 11개 확정 출력에 한정된다. 전체 142개 정답 중 맞게 표시한 비율은 7.75%이며,
노란 경계 42개에서 주황 확정이 0개여서 주황 오표시율은 측정 불가다. 색상 인식이 충분하다는 뜻이 아니다.
OpenCV는 노란 경계 42개 중 13개를 주황으로 표시했으나, 점선 표시 29개 중 실선 그림자를 공백으로 오인한 7개가 False Dashed(24.14%)다.
따라서 OpenCV를 성능이 충분한 우선 대안으로 추천하지 않는다. 두 방식 모두 더 넓은 데이터에서 픽셀·신뢰도 검증이 필요하다.

기존 저속/정차/가림 dense 126개도 새 정책으로 재평가했다. 저속 26, 정차 52, 가림 111개(중복)의 숨김률은 모두 100%다.
표시 전환은 전체 118 인접쌍에서 0이지만 **모두 숨겨진 상태**이므로 안정화 성공으로 주장하지 않는다.
저속/정차의 승인 타입 정답은 0개라 False Dashed·잘못된 실선·주황 오표시율은 측정 불가다.
가림 중 정답이 있는 27개에서 오표시는 0건이나 표시 확정 자체가 0건이므로 확정 정확도는 측정 불가다.
sparse 테스트의 93개 관측/78개 정답은 시간 간격이 커 새 정책에서 모두 숨김이다. 이것으로 전환 안정성을 판정하지 않는다.

## PC 추론 성능과 comma 미검증

각각 새 PC 프로세스에서 같은 미리 추출된 좌우 2 ROI를 5Hz 목표로 32.0초/160회 실행했다.
정규화·분류 시간이며 카메라 수신·전체 투영·추가 표시 정책 비용은 제외한다. RSS는 주기 후 샘플 최대이며 연속 peak 측정값은 아니다.
CPU 100%는 한 코어 기준이고 OFF의 작은 CPU 값은 대기 루프/계측 비용이다. 짧은 native 연산은 Windows 프로세스 시간 카운터에서 검출되지 않을 수 있어 계측값 0을 실제 CPU 사용량 0으로 해석하지 않았다. OFF의 RSS는 ROI를 미리 읽은 벤치마크 대기 프로세스의 값이며, 실제 옵션 OFF에서 분류기나 모델이 실행된다는 뜻이 아니다.

| PC 조건 | CPU | RSS 샘플최대 MiB | 평균 ms | p95 ms | p99 ms |
| --- | --- | --- | --- | --- | --- |
| off | 계측 검출 불가(계측값 0) | 44.66 | 측정 불가 | 측정 불가 | 측정 불가 |
| onnx | 1.414% | 54.94 | 2.971 | 4.060 | 4.307 |
| opencv | 0.146% | 49.71 | 0.657 | 1.006 | 1.373 |

별도 대기 프로세스 대비 RSS 샘플최대 차이는 ONNX +10.29MiB(+23.0%), OpenCV +5.05MiB(+11.3%)다. 실제 장치의 전체 프로세스 ON/OFF 차이는 아니다.
이 PC 벤치마크에서 OpenCV는 ONNX보다 평균 추론 77.9%, p95 75.2%, p99 68.1% 짧았다. CPU 측정값은 89.7% 낮았으나 오분류 문제를 상쇄하지 못한다. OFF CPU는 카운터 검출 한계 때문에 변화율을 계산하지 않았다.

실제 comma는 연결되지 않았다. comma ON/OFF CPU·RSS·추론 지연·modeld/controlsd 주기/지연·프레임 누락은 전부 측정 불가다.
Xiaoge 비교 기준 평균 738ms·CPU 약160%·RSS 약216MiB는 장치 기준이다. 위 PC 수치와 나누어 실차 성능 개선율로 제시하지 않는다.
